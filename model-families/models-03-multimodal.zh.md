# 多模態：當模型張開了眼睛

> 📅 2026-08-04 · 核心概念
> 模型不只看文字了：看圖、聽音、讀影片。深入『視覺編碼器 + LLM』如何組合，以及多模態何時真正值得——OCR、截圖、圖表、無障礙。

---

你終於可以把一張「看不懂的報錯截圖」丟進對話框，然後問它：「這到底是什麼意思？」它讀到了。這就是**多模態（multimodal）**——模型不再只吃文字，它開始張開眼睛、豎起耳朵。

上一站（`models-02-families-tour`）我們逛完模型家族，這篇跳進其中一項讓我們生活改變最大的能力：模型怎麼開始「看」和「聽」。我會先講清楚多模態不是魔法，而是兩個零件拼起來的事實。看完你會知道多模態**什麼時候真的值得用**，以及它**什麼時候會騙你**。

## 先回到那條唯一的原則

整本書的地基（`llmcore-01-next-token`）是：模型其實只會**預測下一個 token**。聽起來好像只能處理文字？對——如果它看到的只有文字。

多模態的關鍵就在這裡：**它把圖片、聲音、影片，全都轉譯成「token 的語言」。** 模型本身沒有變成另一種生物，它只是發現「哦，原來一張圖也可以翻譯成一串我能懂的 token」，然後它照樣用它唯一會的把式——一個字一個字往下猜。

這不代表多模態不重要。恰恰相反：**能把世界翻譯成 token 的能力，決定了模型能不能跨出純文字的牢籠。** 我們每天的工作流裡，有大量的資訊根本不在文字裡——它在截圖裡、在照片裡、在會議錄音裡、在畫出來的圖表裡。多模態，就是那座把這些資訊「翻譯」回文字世界的橋。

## 一張圖是怎麼「進入」模型的

先拆解一張圖片。圖片本質是一大堆數字（每個像素的顏色）。模型要讀它，不能直接吞這些數字，它需要一個翻譯官——**視覺編碼器（vision encoder）**。

兩段式設計是當代多模態的通用骨架，拆成四步看：

#### 切塊

把圖片切成固定大小的小塊（patch），像拼圖一樣。

#### 編碼

每個小塊由視覺編碼器轉成一個向量，捕捉那塊區域的視覺資訊。

#### 對齊

投影層把視覺向量映射進文字 token 的空間，讓兩者能混在一起讀。

#### 融合

視覺 token 與文字 token 一起送入 LLM，模型照樣一個字一個字往下預測。

關鍵心法：**視覺編碼器負責「看懂」，LLM 負責「接話」。** 兩者各司其職，拼成一個完整的多模態模型。它沒有「新的智慧」，只有「新的輸入插頭」。

| 零件 | 它的工作 | 產出 |
|---|---|---|
| 視覺編碼器 | 把圖片 patch 轉成向量 | 視覺 token |
| 投影層 | 把視覺向量對齊到文字 token 空間 | 混合 token 序列 |
| LLM 主幹 | 用「下一個 token」機制融合與接話 | 文字 / 其他輸出 |

## 聲音與影片：同一套配方

圖片是第一個被打開的輸入管道，但絕不是最後一個。**音訊與影片走的是同一套邏輯：先把非文字內容編碼成 token，再丟給同一個 LLM。**

* **音訊**：語音先被轉成文字轉錄（語音辨識），或直接由音訊編碼器變成 token。會議紀錄、語音筆記，就此成為模型的閱讀材料。
* **影片**：影片其實是一串快速變化的圖片。模型把關鍵幀抽出來，逐幀視覺編碼，再搭配時間順序理解「接下來發生什麼」。

這對我們的意義很實際：**今天你手上任何「非文字」的素材，幾乎都有辦法變成模型的輸入。** 不需要再手工把聲音打成逐字稿、把圖片描成文字——直接丟給模型。

## 多模態到底能幹嘛

多模態的出現不是為了「賞圖」，它是為了讓模型能處理**真實世界裡我們隨手就有的輸入**。幾個真正會在你工作上出現的時刻：

* **OCR 與文件**：掃描 PDF、拍一張照片，直接問「這張合約第三頁寫了什麼條件」。模型把圖裡的字讀出來，還懂前後文。
* **截圖除錯**：貼一張錯誤訊息截圖，問「這個報錯是什麼意思」——你不用把字打出來，模型直接讀。
* **圖表與示意圖**：把架構圖、流程圖丟進去，請它解釋「這個系統是怎麼運作的」。它能讀懂佈局而不只是文字。
* **無障礙**：把一張照片變成文字描述，讓視障使用者也能「看懂」。這是很真實、很有價值的應用。

這些場景的共同點：**訊息原本裝在圖裡，傳統文字模型拿不到，多模態把門打開了。** 而當你把它和 RAG 結合（`llm-03-rag`），還能做出「對整批文件截圖提問」的系統。

以 Claude Code 這類終端代理為例：它能在你貼進截圖時直接讀圖，把你手上的除錯現場變成它的輸入（`claude-code` 系列有大量這類流程）。這不是「另一個功能」，這是工作方式本身的改變——**你和模型開始共享同一個螢幕。**

## 一個最小的多模態呼叫

多數多模態模型透過 API 就能接收圖片。結構上只是「對話訊息裡多塞一個圖片欄位」，其餘照舊：

```python&#x20;—&#x20;帶圖提問
# 偽程式碼：結構如此，各家 SDK 略異
messages = [
{ "role": "user", "content": [
    { "type": "image", "image": screenshot_bytes },
    { "type": "text", "text": "這個報錯是怎麼回事？" },
]}
]
reply = client.chat(messages)
print(reply)
```

注意兩個細節：一是**圖片放在內容陣列裡與文字並排**，模型會一起讀；二是**別偷懶直接把整張大圖丟進去**——先在本地縮圖或裁切，能省下可觀的 token 與延遲。

## 多模態的成本：token 不便宜

把圖片翻譯成 token 是有代價的。一張圖可以吃掉**幾百到上千個 token**——比「把一句話說清楚」貴得多。這帶來幾個實際後果：

| 用法 | 大概成本 | 建議 |
|---|---|---|
| 一句文字問題 | 幾十個 token | 最省 |
| 一張小圖 + 一句話 | 幾百個 token | 常見，可接受 |
| 一頁密集文件 | 上千個 token | 能省則省，先裁切再送 |
| 一部長影片 | 極貴 | 只抽關鍵幀 |

所以多模態的實務心法之一是：**能先縮圖、先裁切、先抽幀，就不要整張整部直接丟。** 省下來的都是白花花的錢與等待時間。

> 記住一件事：多模態不是讓模型「更聰明」，而是讓它「看得見」。 它的底層還是那台預測下一個 token 的機器，只是現在能把圖片、聲音、影片翻譯成 token。模型的智慧沒變，它的「輸入頻寬」變大了——而頻寬是要錢的。

## 多模態三種層級，別搞混

不是所有「會處理圖片」的模型都一樣。市面上有三種層級，理解它們能避免誤會：

| 層級 | 它做什麼 | 例子 |
|---|---|---|
| **純視覺理解** | 只把圖表變成描述 | captioning 模型 |
| **視覺 + 文字理解** | 輸入圖+字，輸出文字 | 讀截圖、問圖中問題 |
| **生成 + 理解** | 能讀也能畫出圖片 | 圖生文、文生圖交替 |

大部分「多模態 LLM」屬中間那一層：**讀進圖像、吐出文字**。它能「理解」圖片然後用語言回答你——這對我們絕大多數工作已經非常夠用。讀與生成兼備的模型更強，但也更貴、更難控制。

## 它也有明顯的界線

要誠實承認多模態並不全能。你自己的使用經驗會驗證這幾條界線：

* **它讀的是「被翻譯後的圖片」，不是原圖。** 小字、密集表格、圖片角落的細節，常常會漏。別讓它「逐字報合約」，它會瞎報。
* **它還是會幻覺。** 模型讀圖和讀字一樣，都可能一本正經講錯（`llmcore-05-hallucination`）。圖像輸入並不會讓它變誠實。
* **視覺理解不是真「看」。** 它沒有眼睛，它只有一種特別的 token 解讀方式。它「懂」的是圖像的統計規律，不是人類的觀看。
* **多步視覺推理仍不穩。** 問它「圖裡有幾個紅色的圓形物體」，它可能數錯——數數與空間關係是視覺模型的軟肋。

## 選多模態模型時留意什麼

不是所有「多模態」都同樣可靠，選購與比較時有幾個觀察重點：

| 面向 | 該問的問題 |
|---|---|
| **解析度敏感度** | 它能讀多小的字？密集表格行不行 |
| **定位能力** | 能不能指出「問題在圖的哪個角落」 |
| **多圖推理** | 能不能同時對比兩張圖、找出差異 |
| **一致性** | 同一張圖問三次，答案穩不穩定 |

用你自己的真實截圖與文件去測（`models-06-evaluation` 的方法），比相信官網 demo 可靠得多——demo 往往只挑模型擅長的圖。

## 所以多模態對你意味著什麼

一句話：**它給了你的工作流程一條新的輸入通道。** 以後遇到圖、遇到音，你不再需要手動把內容轉成文字再問——直接把原始素材丟進模型就好。

在多模態模型的世界裡，最實用的原則就是：**「如果有圖，別只貼文字描述；直接給圖。」** 讓視覺編碼器去做它擅長的事。用 `models-06-evaluation` 那套「你自己的任務集」去測各家多模態模型對你圖片的表現，比任何官宣都誠實。

下一步，從「看得見」升級到「想得深」——我們談談**推理模型**：那些會在回答之前，自己先想很久的模型（`models-04-reasoning`）。

#### Q: 為什麼多模態模型能讀圖片，而傳統文字模型不行？關鍵差別在哪？

* 它有一個能畫圖的擴充功能

* 它在網路上下載了圖片內容

* 視覺編碼器把圖片轉成視覺 token，再交給 LLM 用「下一個 token」機制處理

* 它的參數比文字模型多十倍

> 💡 多模態的關鍵是視覺編碼器把圖片翻譯成視覺 token，模型再用它唯一的那招——預測下一個 token——把圖像理解融入文字回應。智慧沒變，輸入頻寬變大了。
