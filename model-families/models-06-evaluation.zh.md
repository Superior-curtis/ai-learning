# 評估與基準：怎麼量『模型多強』

> 📅 2026-08-04 · 深入研究
> MMLU、程式題、數學評測、排行榜——我們怎麼量化『多強』；它的三大漏洞（飽和、作弊、測試污染）；以及為什麼你自己的任務集才是最誠實的評量。

---

你打開任何一篇新聞，都會看到「O 家模型又在排行榜奪冠」「新模型 MMLU 突破 90%」。但你我都知道，**模型好不好用，跟排行榜的數字能不能真正對應，是兩回事。**

前面五篇（`models-01` → `models-05`）我們把模型看了個遍。這篇是最後一站，處理那個最基本、也最容易被忽略的問題：**我們到底怎麼公平地量「一個模型多強」？** 答案比你想的還要「不科學」。

## 先懂基準：把「強」切成一道道題目

要量「多強」，光靠「它聊天很順」這種感覺不夠。所以學界與業界發明了**基準（benchmark）**：一組固定、有標準答案的題目，讓模型照題作答，然後算分。常見的幾類：

| 基準 | 在測什麼 |
|---|---|
| **MMLU** | 多門學科選擇題——人類知識廣度 |
| **程式題（HumanEval / MBPP…）** | 給一個函式需求，寫出能通過測試的程式 |
| **數學題（GSM8K / MATH…）** | 多步計算與推理，答案唯一 |
| **長文理解 / 摘要** | 讀長文件後的理解與整理 |

分數越高，代表它在**那一類題目**上越強。注意是「那一類」——MMLU 高分不代表它寫程式強，也不代表它懂你公司的業務。

## 為什麼不能只看一個基準

有個常見誤區：以為「只有一種『多強』」。但模型的能力是**多維的**——它可能學識淵博但不會寫程式，可能程式頂尖但長文理解普通。單一基準像「只量身高不看體重」，註定看不全。

所以成熟的做法是**看一組基準的剖面**：通識、程式、數學、長文、推理各挑一兩個。`models-04-reasoning` 提到推理模型在數學很強，在創意題反而差——這在單一總分裡會被洗掉，只有剖面圖看得見。

## 排行榜：把一堆基準揉成一個名次

**排行榜（leaderboard）**把多個基準的分數，加權平均成一個總分，排成一列。方便歸納，卻藏著兩個陷阱：

* **權重是主觀的**：誰決定 MMLU 該佔 30% 還是 50%？不同加權會排出不同的冠軍。
* **總分稀釋資訊**：一個「全都 85 分」的平庸模型，可能贏過「數學 95、對話 60」的偏科高手，但後者對你可能更有用。

所以排行榜適合「快速掃一眼誰在領先群」，不適合當作「你該用誰」的聖經——這正是 `models-02-families-tour` 那句「別被排行榜綁架」的實證。

## 基準的三大漏洞：它沒你想的誠實

就算基準的出發點是好的，實務上它有三大硬傷：

1. **飽和（saturation）**：模型一代比一代強，很多基準的分數逼近天花板（90%+），題目對前段模型「太簡單」，已經分不出高低。欄位太容易，尺就失去刻度。
2. **作弊（gaming / overfitting）**：有些團隊會**針對特定基準調參**——讓模型在 MMLU 上漲分，但真實世界任務沒變強。分數變成「練出來的假象」。
3. **測試污染（contamination）**：基準題目常常**早就混進訓練資料**。模型可能「背過」這些題，於是你量到的不是推理，是記憶。這跟 `llmcore-05-hallucination` 是硬幣的兩面——背過就答對、沒背過就編。

## 為什麼「強」的定義一直變

說到底，「強」是相對的、會漂移的標準。三件事讓它一再變動：

1. **對手變強了**：去年 90 分封頂，今年 95 分是常態——分數本身不變，意義變了。
2. **任務變了**：兩年前沒人測多模態的圖表理解，現在這是重要能力。基準要一直「補題」才追得上時代。
3. **模型在「順著尺」長**：這跟作弊不同，是廠商真的朝排行榜想考的方向優化——短期像作弊，長期就是「普世能力」的演化。

理解「強」是動態的，能讓你少抓狂：**一張去年的排行榜，參考價值遠低於一張今年的。** 這跟 `models-02-families-tour` 那句「型號是隨時要更新的資料」是同一個提醒。

## 那我們到底該信什麼：你自己的任務集

正因為基準有這些漏洞，實務上最誠實的評估，是**一套你自己的、真實的任務集（eval set）**。

做法樸實到有點無聊，卻比任何排行榜都貼近你的需求：

#### 蒐集

收集你真實會遇到的輸入——使用者真的會這樣問、產品真的會收到這種資料。

#### 標答

為每題寫下「理想答案」或可打的評分標準。

#### 跑分

讓候選模型對每題作答，用你的標準打分。

#### 對比

同一套任務，跑幾家模型；或同一家模型的不同版本。

這是 `models-02-families-tour` 那套「用你自己的題目測各家」的正式版本，也是 `security-03-evals` 在安全領域用的同一套邏輯。

## 最少要多少題才有效

你不需要一百分鐘就搞定。常被人高估的點是「題數」，被低估的是「貼近度」。關鍵不是題目多，而是**它們要真的是你工作會碰到的**。

| 類型 | 例題方向 |
|---|---|
| 正確性 | 這題的標準答案是什麼 |
| 格式 | 它有沒有照你要求的格式輸出 |
| 風格 | 語氣、長度、是否像你品牌 |
| 邊界 | 輸入很怪、很長、很含糊時它怎麼接 |
| 穩定度 | 同一題問三次，答得穩不穩 |

## 從人肉打分，到「以模型評模型」

等你任務集長大了，人肉每題打分會累死。業界開始用**「以模型評模型」**——找一個（通常是封閉、較強的）判斷模型，照你寫的評分標準替小模型打分。它快、一致，但也有風險：判斷模型自己也可能誤判、或吃進偏見。所以高風險的題，最終還是留給人眼把關。

> 記住一句話：基準與排行榜是「別人的眼光」，你的任務集才是「你的眼光」。 基準可以飽和、可以作弊、可以被污染，唯獨你自己那幾十道真實任務，量到的是「它對你有多強」——那才是你唯一該信的數字。

## 把評估變成你的「回歸測試」

任務集最大的價值，不是「買模型那一刻」用一次，而是**長期當作回歸測試**。每當你改了提示詞、換了 RAG 的向量庫、或更新了模型版本，就跑一遍任務集，看分數有沒有意外下滑。

| 變動 | 該做的評估 |
|---|---|
| 改提示詞 | 確認原先答對的題沒被改壞 |
| 換模型 / 版本 | 對比分數升降，決定要不要升級 |
| 改 RAG 或切塊 | 確認檢索品質沒退化 |
| 加新功能 | 擴充任務集，驗證新能力 |

這正是 `security-03-evals`、`rag-04-evaluating` 這些系列在同一套哲學下的應用：**每一次改動，都要有一把量它的尺。** 沒有回歸測試的系統，改一次壞一次，而且往往是悄悄壞。

## 給自己一個小型的評估開場

別等「完美」，直接動手。一個最陽春的開始：

```python&#x20;—&#x20;最小評估雛形
# 偽程式碼：只做「收集 → 跑 → 打分」三件事
qas = [                       # 你的真實任務
{"q": "用三句解釋多模態", "ideal": "...載明標準答案..."},
...
]
for model in ["openai", "anthropic"]:
  for qa in qas:
      out = model(qa["q"])
      score = judge(qa["ideal"], out)   # 人肉或模型評
```

從**十五道**真實任務開始就有效。重點是它要是你的，不是抄別人的。

## 一句話總結

「模型多強」沒有唯一答案——只有「對誰」、「對哪類題」的強。基準與排行榜給了一個方便的「別人的眼光」，但飽和、作弊、污染三座大山讓它不那麼可靠。真正可信的，是**你自己蓋的那把尺：一套真實任務集**。

到這，`models-` 這個系列（`models-01` → `models-06`）就講完了：開放 vs 封閉、家族導覽、多模態、推理、小模型、評估。你現在對「模型是什麼、怎麼選、怎麼量」已經有完整的地圖。

下一步，我們把焦點從「模型本身」轉到「怎麼指揮它」——**提示工程**，那才是讓模型變好用的真正槓桿（`prompt-01-basics`）。

而當你開始指揮模型、開始改提示詞與 RAG 時，記得隨身帶著本系列最後這一課：**每次改動都跑一遍你自己的任務集。** 那是讓系統「越改越好、而不是越改越亂」的保險。

#### Q: 你是一位產品經理，要決定該採用哪家新模型。下列哪個評估方式對『你的產品』最誠實？

* 看最新的排行榜冠軍

* 用 15 道你產品的真實輸入跑一遍，用你的標準打分

* 只信廠商宣稱的 MMLU 分數

* 直接看模型參數有多大

> 💡 基準和排行榜會飽和、被作弊、被污染，廠商分數更只是行銷。真正誠實的評估，是拿你產品的真實輸入、用你自己的評分標準去測——那才是『對你產品』多強的答案。
