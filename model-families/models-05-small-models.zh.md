# 蒸餾與小型模型：把大象裝進手機

> 📅 2026-08-04 · 核心概念
> 小模型怎麼『拜大模型為師』？蒸餾是什麼、為什麼小型模型遍地都是（端側、本地、便宜），以及它跟微調、LoRA、量化的關係。

---

2023 年大家都在比「誰家模型最大」。到了 2025 年，風向忽然變了：大家開始比「誰能把一個很強的模型，壓進手機、跑在筆電上、還快得嚇人」。這背後靠的就是一招老祖宗智慧——**蒸餾（distillation）**。

上一篇認識了「想很久」的推理模型（`models-04-reasoning`）。這篇看「小」的力量：為什麼你桌上那台小模型，其實偷偷練成了巨人的七成功力，以及它跟微調、LoRA、量化之間那層剪不斷的關係。

## 蒸餾：讓小模型「拜大模型為師」

想像你不可能讀完一百萬本書，但你找了一位讀過的博士，天天把博士的筆記背下來——你最後懂的，大概有博士的七八成。**蒸餾就是這個道理。**

做法是：用一個已經很強的「老師」大模型，餵它一堆問題，收集它的答案（甚至包含它的推理過程）；再用這些「老師的答案」當作訓練資料，去教一個「學生」小模型模仿。

| 角色 | 在做什麼 |
|---|---|
| **老師模型** | 大而強，負責產生「好答案」當教材 |
| **學生模型** | 小而快，學習老師的答案與推理模式 |
| **教材** | 老師對大量輸入的輸出（含推理） |

整個流程拆成四步：

#### 準備題目

準備大量多樣的問題集，涵蓋你想讓小模型學會的範圍。

#### 老師出答案

讓大模型對每題作答，收集高品質答案（最好含推理）。

#### 學生學習

以「問題 → 老師答案」為訓練資料，訓練小模型模仿。

#### 驗證收斂

用留出的測試題確認小模型真的有學會，而不是背書。

關鍵心法：**小模型學的不是「世界」，而是「老師怎麼答題」。** 它複製的是行為與輸出分布，不必複製老師的參數量。這就是為什麼「蒸餾」能讓小模型「小而強」——它站在老師的肩膀上。

## 為什麼小型模型遍地都是

蒸餾之所以爆紅，是因為「能塞進口袋的模型」解鎖了三件大事：

* **端側（on-device）**：手機、筆電、穿戴裝置能直接跑模型，資料不出門、離線也能用。
* **本地**：你自己的機器就能跑（`local-01-ollama` 就是這領域的工具），不用上傳任何東西到雲端。
* **便宜**：推理成本低到可以大規模呼叫，對預算敏感的新創尤其香。

| 優勢 | 為什麼 |
|---|---|
| **隱私** | 資料留在你的設備上 |
| **延遲** | 不必等網路來回，秒回 |
| **成本** | 算力需求小、單價低 |
| **普及** | 人人都能跑，AI 不再是雲端專利 |

## 在本地跑一個小模型，其實很簡單

現代工具把這件事變成幾行指令。以 Ollama 為例（`local-01-ollama` 有完整教學）：

```bash&#x20;—&#x20;本地跑一個&#x20;8B&#x20;小模型
# 安裝後，一條指令就能下載並跑起來
ollama run qwen2.5:7b

# 然後你就能在終端裡直接問它
>>> 用一句話解釋蒸餾
# 蒸餾是用大模型的答案訓練小模型，讓小模型繼承大模型的知識。
```

不用雲端、不用付費、不用把資料交給任何人——這就是小型模型最迷人的地方。

## 小模型與微調、LoRA 的親戚關係

很多人把「蒸餾、微調、LoRA」混在一起，其實它們是**三種不同的工序**，可以一起上：

* **微調（`train-02-finetuning`）**：在既有模型上，用**你的資料**繼續訓練，教它你的領域或風格。
* **LoRA（`finetune-02-lora`）**：一種「便宜微調」的技術，只調整一小批額外參數，就能把模型導向特定任務。
* **蒸餾**：把「大模型的能力」**壓縮轉移**到小模型。

實務上它們常**接力使用**：先蒸餾出小模型，再用你的資料微調它，讓它既小又懂你——這就是本地 AI 應用的標準配方。要再往下壓，還有**量化（`local-06-quantization-tiers`）**把參數精度降下去、檔案再瘦一圈。

## 知名的蒸餾實例

蒸餾不是紙上談兵，業界已經有幾個教科書級的例子：

* **Llama 的衍生海**：`models-02-families-tour` 提過，Llama 被微調與蒸餾出數不清的衍生模型，成為開源社群的地基。
* **DeepSeek-R1 的蒸餾**：DeepSeek 公開把自家推理模型（`models-04-reasoning` 那類）蒸餾進 Qwen 與 Llama 的 1.5B～70B 學生模型，讓小模型也學會「先想想再答」。
* **各家「mini / small」版本**：幾乎每家封閉廠商都出了自己的小型版，用蒸餾把旗艦的功力壓進成本更低的小身板。

這些例子的共同點：**蒸餾讓「頂尖能力」不再被綁在最大、最貴的模型上。** 它是把能力「傳下去」的管道。

## 用比較滑桿看：大模型 vs 小模型

同一道題，兩個模型的心智狀態完全不同。想像你在兩個選項之間滑動：

#### 對照 / Comparison

左邊是「把難題想透」的智者，右邊是「馬上給你答案」的工人。**關鍵不是哪邊比較好，而是你手上這道題需要哪邊。**

## 選小模型的幾條實務建議

真要挑一個小模型進你的產品，這幾條可以省很多冤枉路：

* **先定任務，再定尺寸**：你的任務是「摘要」還是「回答領域問題」？前者 3B 就夠，後者可能要 8B 以上。
* **看參數，更要看蒸餾品質**：同是 7B，蒸餾自好老師的，遠勝隨意縮小的。廠商的說明與基準（`models-06-evaluation`）都要看。
* **先量化再決定**：同樣權重，4-bit 量化可能省一半記憶體（`local-06-quantization-tiers`）。小模型 + 量化，常常才是真的「夠小」。
* **自己跑一遍**：本機就能跑（`local-01-ollama`），直接拿你的真資料測，比看規格表可靠。

順帶一提，很多人誤以為「小模型 = 開源、大模型 = 封閉」。其實蒸餾這條路**兩邊都走**：開放社群蒸餾 Llama/Qwen，封閉廠商也蒸餾自家的 mini 版——它純粹是「能力壓縮」的手法，與開放封閉無關（`models-01-open-vs-closed`）。

## 可是小模型聽起來太美好，有沒有坑

當然有。誠實列出幾個：

* **上限就在那**：再怎麼蒸餾，小模型的頂點通常低於大模型。它適合「夠用」的任務，不是「最強」的任務。
* **推理與極難題不行**：上一站的推理模型（`models-04-reasoning`）說「想很久才答」，小模型常常**想不動**。
* **資料品質決定一切**：老師給的教材若是髒的，學生的回答也髒。蒸餾的品質上限，是老師的品質上限。
* **學生會「學到老師的壞習慣」**：老師的偏見、幻覺傾向，也會一起被複製過來。

所以正確姿勢是：**大模型當「智者」，小模型當「工人的化身」。** 需要深度時叫智者，需要速度與隱私時叫工人。就像一家公司不會讓每個人都去開董事會——大部分日常雜務，交給又快又便宜的小模型剛剛好。

## 一句話總結

小型模型不是「比較笨的模型」，而是「**用蒸餾從老師那壓縮來的濃縮模型**」。它犧牲一點廣度，換來能塞進手機、跑在本機、又便宜到可以大量使用的三件好事——代價是對抗不了真正的極難題，也擋不住老師的壞習慣。

不過小模型也不是「小就萬事足」，它還有一招讓它更小的神技：**量化**，把參數精度降下去、檔案瘦身——這正是 `local-06-quantization-tiers` 要講的實戰。

> 記住一句話：蒸餾不是「小模型變強」的魔法，而是「把老師的答案當教材，讓學生模仿」。 它複製行為，不複製參數量。要再疊上微調與 LoRA，才能讓小模型既小、又快、又懂你。
