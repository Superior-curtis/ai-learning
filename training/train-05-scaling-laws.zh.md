# 規模法則：為什麼越大越不同

> 📅 2026-08-04 · 深入研究
> 把模型、資料、算力一起放大，損失就按『冪律』穩定下降，甚至冒出預料之外的新能力。這是 AI 圈最該懂的一條曲線。

---

為什麼 AI 圈敢賭「模型越大越強」？背後不是直覺，而是一條**被反覆驗證的數學規律：規模法則（scaling laws）**。它說：把模型參數、訓練資料、算力一起放大，模型的「語言損失」會按**冪律**穩定下降——可預測地變強。

更戲劇的是，某些能力**不是慢慢變好，而是突然冒出來**（emergence）。這就是「越大越不同」的真正含義。

## 一句話

> 給足資料與算力，更大的模型 = 穩定地更會「猜下一個詞」（損失更低）。而且這條線**可以預測**，所以可以靠它計畫多少錢、多少 GPU。

## 三個可以放大的量

規模法則把「放大」拆成三根槓桿，全都能降低損失：

| 槓桿 | 例子 | 觀測結果 |
|---|---|---|
| **模型參數 N** | 7B → 70B → 700B | 參數越多，損失越低 |
| **訓練資料 D** | 1T → 10T token | 資料越多，損失越低 |
| **算力 C** | 花更多 GPU 時間 | 大致把前三者一起推進 |

```text
損失（越低越好）
│          •
│       •  ← 歷史觀測點
│    •   （每個模型一筆，連成一條直線）
│ •
└───────────────────→ 規模（對數刻度）
在對數–對數圖上，冪律 = 一條直線 → 可外推預測
```

關鍵是**「對數–對數圖上的直線」**：冪律（loss ∝ size的負指數）在對數圖上是一條直線。所以你拿了幾個數據點，就能外推「再多花一倍的錢，損失會降到多少」——這是 `economics`（Part 4）裡「AI 公司敢燒錢」的數學根據。

## 算力最優配置：Chinchilla 法則

「同時放大三樣」聽起來簡單，但有個陷阱：**參數與資料要平衡，不是無腦加倍。**

OpenAI / DeepMind 發現：對一筆「固定算力」，存在一個**最優的「參數 vs 資料」比例**。經典的 Chinchilla 研究指出，很多模型其實「資料餵太少」——模型有 70B 參數，卻只吃了「不足以讓它充分發揮」的資料。把參數砍小、資料補足，同樣算力下反而更強。

```
同樣算力預算下：
  舊做法：70B 參數 +  1T token   （資料不夠，潛力未榨乾）
  Chinchilla：40B 參數 + 2.5T token  （更平衡 → 同樣算力更強）
```

> 記住精神：「越大越好」是對的，但要在『參數 ↔ 資料 ↔ 算力』三者平衡的意義上。 只無腦堆參數、卻餵不夠資料，是浪費算力。

## 突現能力：不只是「更大」，是「突然變更強」

規模法則最迷人的部分是**湧現（emergence）**：某些能力在小模型上幾乎是零，但只要規模跨過一個門檻，就**突然**冒出來。

* 8B 模型：算三位數加法，一直錯。
* 70B 模型：突然會算了。
* 小模型：不會「援引格式引用來源」；大模型：突然會。

就像水在 0°C 才結冰——不是「越來越冰」，而是**相變**。這解釋了為什麼「這模型小了 10 倍，能力掉了 90%」常讓人意外：能力不是線性縮放，是有門檻的。

```text
能力（測驗分數）
100%│           ╭──────→ 突然跳升
│        ╭──┘
│      ╭─┘
│    ╭─┘
0% └───┴──────────────────→ 規模
小        中等   大
幾乎為零      某些能力>門檻後「出現」
```

## 「湧現」有爭議？

老實說：「湧現」有一部分是**測量假象**——很多分數是「通過 or 不通過」的二元指標，小模型差一點就差很多，看起來像突然跳升。改用「連續的分數」去看，其實可能是平順地慢慢變好。

> 結論別走極端：「規模讓能力以非線性方式成長」是真的，「某個具體湧現門檻」則要看測量方式。 但「越大越不同」的直覺，被這條曲線抬成了可預測的工程定律。

## 限制在哪裡：資料要見底了

規模法則不是無限免費午餐，它有盡頭——**資料**。

* 模型每大一檔，就需要更多資料「配得上」它的參數（Chinchilla）。
* 但**人類寫的文字是有限的**：全網路優質文字就那麼多。
* 已經有報告估算，照目前吃法，**優質人類資料可能在幾波內被用完**。

這逼出幾個出路：合成資料（`train-04` 提過）、開源社群合作、或轉向多模態（影片、圖像還沒被吃穿）。但資料上限，值得你記住：**規模法則的瓶頸，最後會是「沒菜了」。**

## 這意味著什麼

* **對公司**：燒錢是「按曲線買未來」——有數學根據，不全是賭。
* **對開源**：小模型永遠追不上旗艦的「湧現」，但 LoRA、蒸餾（`models-05-small-models`）讓小模型夠用。
* **對你**：看到「350B 參數」別只覺得「又是行銷」，那是他們對「資料＋算力」配置的宣告。

#### Q: Chinchilla 法則要傳達的核心調整是什麼？

* 參數越多永遠越好，資料其次

* 對固定算力，存在「參數 vs 資料」的最優平衡，資料太少會浪費模型潛力

* 資料越多永遠越好，參數其次

* 應該完全放棄大模型改用小模型

> 💡 Chinchilla 發現很多模型『資料餵不夠』：對固定算力，砍點參數、補足資料反而更強。核心是『參數↔資料↔算力』三者要平衡。
