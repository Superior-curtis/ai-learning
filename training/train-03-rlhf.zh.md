# RLHF：讓模型符合人類偏好

> 📅 2026-08-04 · 核心概念
> 預訓練完的模型天才但不聽話：會說謊、會擺爛、幫倒忙。RLHF 用『人類打分數』引出一個獎勵模型，再教模型學會『做人』。

---

到了這裡，模型已經很會說話、也很會推理，但它還不是一個「好用」的助手。它可能：

* 一本正經編造答案（幻覺，`llmcore-05`）。
* 被問到不會的，硬擠出胡話，而不是說「不知道」。
* 拼命討好你，你說是黑它就跟著說黑（迎合病，sycophancy）。
* 拒絕幫助、或幫倒忙。

把模型從「天才但難相處」變成「真的好用」，靠的是一道工序：**RLHF（Reinforcement Learning from Human Feedback，基於人類回饋的強化學習）**。它是 ChatGPT 類產品當年一鳴驚人的關鍵一步。

## 完整生產線：預訓練 → 指令微調 → RLHF

現代「助手型」模型的標準三步：

```text
Step 1  預訓練（pre-training）     學語言與知識（猜下一個詞）
Step 2  指令微調（SFT）           學「乖乖回答問題」的格式與行為
Step 3  RLHF                     學「符合人類偏好」——有用、誠實、無害
```

`Step 2` 的 SFT 本質也是微調（`train-02`）：拿一堆「人類如何回答問題」的範例，把模型的「接話」格式調整成「回答問題」。但它只會「照著人類範例模仿」，還不夠——**人類範例有限，無法涵蓋所有情況**。RLHF 就是在這之上，教模型「哪些行為更好」。

## 一鍋三料：RLHF 的三個角色

RLHF 需要三方協作：**人類回饋**、**獎勵模型**、**要訓練的策略模型**。

**1. 收集人類偏好資料（最燒錢的一步）**

找工人，給它兩個模型輸出，問「哪個更好」。幾十萬對「比較」累積起來，就是人類偏好的「地圖」。

```
模型輸出 A：好的，我會跟進你的專案進度……      ← 有用、具體
模型輸出 B：好的😊👍                            ← 敷衍但無害
人類工人：A 比較好 → 記下一筆「A 勝 B」
```

**2. 訓練獎勵模型（reward model）**

用這些「A 勝 B」的比較，訓練一個小型「評分器」：給它一段輸出，它輸出一個分數——**預測人類會多喜歡這個回答**。它學會「人類覺得哪種話更好」。

**3. 用獎勵模型教策略模型（PPO 強化學習）**

讓策略模型繼續生成，每個回答交給獎勵模型打分；分數高的方向就強化、分數低的就壓制。模型在無限生成中，慢慢被「獎勵訊號」塑造成「更符合人類偏好」。

```text
人類打分數（A 勝 B）
↓
獎勵模型：學會「打分」
↓
策略模型：生成 → 獎勵模型打分 → 高分強化 / 低分壓制
↓         （重複幾百萬步）
「更有用、更誠實、更無害」的模型
```

## 這跟「對齊」（Part 5）什麼關係

你可能會想，這不就是 `alignment` 的內容嗎？先釐清：

* **RLHF 是「做法」**：訓練階段的一套具體技術（讓模型符合人類偏好）。
* **對齊（alignment）是「目標/領域」**：讓 AI 的目標與人類意圖一致——範圍大得多，涵蓋安全、倫理、AGI 風險等（見 `align-01-what-is-alignment`）。

RLHF 是**對齊在「訓練流程」裡的落地步驟之一**，但它不是對齊的全部。對齊還包括不能用「打分」解決的問題（例如模型太會討好、或根本性的安全邊界）。

## 你不能（也不需要）自己跑 RLHF

老實說：**RLHF 不是給你做的。** 理由：

* **要大量人類評分**：幾十萬對比較，需要專業標註團隊與錢。
* **要強化學習基建**：PPO 訓練極度吃工程與算力。
* **有現成的**：你用 API 拿到的模型，早就經過完整 RLHF——你用的就是「成品」。

所以對 99% 的人，RLHF 這一段是「看懂了、感謝、直接用」就好。你真的想控「行為」，多半用**提示詞**或**開源已對齊模型**更實際。

> 一句話記住 RLHF 的位置：它是把「天才但不聽話」變成「好用又靠譜」的收尾工序，由寡頭 labs 完成；你是那個「用成品」的人。

## 後起之秀：DPO（不用獎勵模型）

RLHF 依賴「人類比較資料」＋「強化學習」，工程很重。近年流行更輕的做法 **DPO（Direct Preference Optimization）**：也用「A 勝 B」的比較資料，但**跳過獎勵模型與強化學習**，直接改損失函式讓模型偏愛優選項。

```
RLHF：比較資料 → 獎勵模型 → 強化學習（PPO）→ 對齊
DPO ：比較資料 → 直接改損失 → 對齊（不需獎勵模型 / 不需 RL）
```

好處是便宜、穩定、好複製。近年不少開源對齊都改用 DPO 風格。核心概念仍是同一套：**用「人類偏好」這個訊號，教模型怎麼「對人類更好」。**

## 一句總收

模型的一生是這樣被「教」出來的：

1. **預訓練**——一個天才誕生（會講話，但不聽話）。
2. **指令微調（SFT）**——學會回答問題的格式。
3. **RLHF / DPO**——學會「有用、誠實、無害」，成為一個你可以用的助理。

下一步，去認識這些模型的**種類**：開放與封閉、不同家族各有什麼特質——`models-01-open-vs-closed`。

#### Q: RLHF 中「獎勵模型」的主要任務是什麼？

* 替模型生成更多的訓練資料

* 學「人類比較」後，給任何一段輸出一個『人類會多喜歡』的分數

* 把模型輸出轉成 JSON

* 幫人類也寫一個更好的提示詞

> 💡 獎勵模型從「A 勝 B」的人類比較中學習，變成一個『優先訊號』的打分器：策略模型靠它的高分強化、低分壓制，被塑造成更符合人類偏好。
