# 白話 AI 名詞表：聽懂大家在聊什麼

> 📅 2026-08-04 · 使用教學
> token、RAG、AGI、幻覺、微調……每篇文章都塞滿縮寫。這篇把所有常見名詞，用白話一次講清楚，並告訴你該去哪一篇深入。

---

你打開一篇 AI 報導，第一眼就是一串「token、RAG、AGI、幻覺」——如果你覺得被縮寫淹沒，那不是你的問題，是這圈子太愛造術語了。

好消息是：真正常見的詞其實只有十幾個，而且每一個都對應到本書裡某篇「那篇才講得深」的文章。這篇就是那張「查詢表」——用白話各講一句，再告訴你該去哪兒細讀。

## 先把地基接上

整本書的出發點只有一句話：**LLM 做的事情，就是「猜下一個詞」**。它讀過海量文字之後，學會了「看到目前的文字，下一個最可能是哪個詞」。（想知道為什麼這句短短的話能生出會寫文章、會寫程式的東西，去讀 `llmcore-01-next-token`。）

這個「猜」，就是下面幾乎所有名詞的**最後一塊拼圖**。你把這一句記牢，接下來的詞都是它的延伸。

## 最常被混用的「三字母」詞

`intro-01` 已經用一張蛋糕圖把關係理過一遍，這裡只留一句話的精華。這五個詞是層層包含，不是同一件事：

| 名詞 | 一句話 | 深入看 |
|---|---|---|
| **AI**（人工智慧） | 讓機器做「本來要人腦才能做的事」的總稱 | `intro-01-what-is-ai` |
| **ML**（機器學習） | 其中一種做法：不寫死規則，從資料裡學規律 | `intro-01-what-is-ai` |
| **DL**（深度學習） | 一種熱門技法：用很多層的神經網路學 | `intro-01-what-is-ai` |
| **LLM**（大型語言模型） | 目前最紅的模型類型：專精語言，靠「猜下一個詞」 | `llmcore-01-next-token` |
| **AGI**（通用人工智慧） | 理想中的「什麼都會」的 AI，今天還沒達成 | `intro-05-agi` |

> 關鍵是包含，不是等號：所有 LLM 都是 DL，所有 DL 都是 ML，所有 ML 都是 AI——但反過來不一定。AGI 則是「未來願景」，現在沒有任何系統稱得上它。

這五個詞最實用的分類法：**看到「AI／ML／DL」八成在講學科或技術路線，看到「LLM」在講「具體的產品主角」，看到「AGI」在講「還沒有實現的願景」。** 這樣一拆，標題裡的縮寫立刻不再嚇人。

## 用產品時一定碰到的那三個詞

一旦你真的打開 ChatGPT 或 Claude，第一個撞上的就是這三個。它們決定「這東西能多大、多貴、多可靠」。

| 名詞 | 一句話 |
|---|---|
| **Token** | 模型讀的不是字或詞，而是一小塊一小塊的「文字單位」；它同時決定記憶上限、計費和速度 |
| **Context Window**（上下文窗口） | 模型一次最多能「同時看到」多少 token；窗口外的內容，它等於從沒看過 |
| **Hallucination**（幻覺） | 模型會自信地胡說八道——不是騙你，而是它只學會「哪個詞最順」，沒學會「哪個事是真的」 |

這三個是「AI 出了名的坑」的根源。Token 有多坑（尤其中文讀起來特別貴）在 `llmcore-02-tokens`；「窗口」為什麼等於記憶上限，在 `llmcore-03-context`；而幻覺是整個產業防禦的頭號對象，詳見 `llmcore-05-hallucination`。

換個方向看，這三個坑其實是「可以辨認、可以應付」的：

| 你遇到的症狀 | 這是哪個詞 | 第一步該做什麼 |
|---|---|---|
| 它好像忘了三小時前講過的話 | 窗口 | 把關鍵訊息重新貼回去，別指望它記得 |
| 帳單比預期貴很多（尤其貼了一堆中文） | token | 精簡輸入、分段處理 |
| 給了一個精確卻可疑的數字／來源 | 幻覺 | 交叉查證，別把它的語氣當證據 |

#### 想再挖深一點？展開這些

「token 到底怎麼切？」：英文常用詞幾乎一詞一個 token，罕見字會被拆成好幾塊；中文每個字常就是 1 個 token 以上，所以同一句話中文常常比英文貴 2–3 倍。\n\n「窗口 8K 和 200K 差在哪？」：8K 大概只塞得下幾頁文章；200K 可以放一本幾百頁的書。窗口越大越好用，但也更貴。\n\n「幻覺真的防得住嗎？」：防不住「完全不出現」，但可以用 RAG 給它證據、要求它引來源，把發病率壓低到可用的程度。

## 讓 AI「變有用」的那四個詞

基礎模型只會「接話」。真正讓它在你的資料、你的工具、你的流程裡派上用場的，是下面四個：

| 名詞 | 一句話 | 深入看 |
|---|---|---|
| **Fine-tuning**（微調） | 在已預訓練的模型上，用「你自己的資料」再練一下，教它一門專長 | `train-02-finetuning` |
| **RAG**（檢索增強生成） | 在模型回答前，先從你的資料庫把相關段落「撿回來」塞進提示詞，讓它照著證據說 | `rag-01-what-is-rag` |
| **Agent**（代理） | 不只是「回答」，而是一步步自己動手把任務做完的系統 | `agents-01-what-is-agent` |
| **MCP**（模型上下文協定） | 統一「Agent／模型怎麼連上你的工具」的開放標準，類似「工具界 USB」 | `agents-03-mcp` |

如果你只是想「讓模型用我家的知識回答」，先從 RAG 下手——它最便宜、最好上手、也最能立刻止血知識凍結與幻覺。微調則要等你確認「改行為、改格式」是剛需時再考慮。

#### 對照 / Comparison

一句話記法：**RAG 是「給它看書再考它」，微調是「把它教成習慣」。** 兩者怎麼選的完整決策，見 `finetune-01-finetune-vs-rag`。

## 看到術語，先丟進三個格子

以後再碰到沒見過的縮寫，不用慌。先把它丟進這三個問題：

1. **它是「模型行為」還是「工程做法」？** 描述模型本身的（token、窗口、幻覺、推理）去 `llmcore-*` 找；教你怎麼做的（微調、RAG、Agent、MCP、量化、提示詞）去 `train-*`、`rag-*`、`agents-*`、`prompt-*` 找。
2. **它改的是「模型」還是「輸入」？** 微調改模型權重；RAG 改輸入內容。一問就分家。
3. **它屬於「現在」還是「願景」？** 需要等未來的（AGI、對齊）是一類；今天就上線的是一類。前者去 `intro-05-agi`、`align-*` 系列，後者就在本書前半部。

把這個分類練熟，比背一百個名詞還有用。

## 當縮寫出現在你的工作場合

術語不是拿來考試的，是拿來開會、看新聞、讀文件的。把它翻譯成白話，場景就通了：

| 同事／新聞這樣講 | 白話意思 |
|---|---|
| 「這版用了 RAG，所以比較少胡說」 | 先撈資料再回答，幻覺變少了 |
| 「開個新 session，不然窗口滿了」 | 對話太長、超過記憶上限，得重開 |
| 「這模型沒微調過」 | 沒用你家資料特訓過，是通用版 |
| 「我們做個 agent 去跑這個流程」 | 讓 AI 自己一步步把流程做完 |
| 「透過 MCP 接進我們的系統」 | 用標準協定讓 AI 能操作你的工具 |

## 三個最容易用錯的詞

最後用三個「日常小誤用」收尾，因為它們最常在對話裡出錯：

| 常被用錯 | 正確理解 |
|---|---|
| 把「LLM」講成「AI」 | LLM 只是 AI 的一種，別把部分當全部 |
| 把「幻覺」講成「說謊」 | 幻覺沒有意圖，是「沒在查證」的必然結果 |
| 把「RAG」講成「記憶」 | RAG 是每次現撈，不是「記住了你的事」 |

這三個誤用背後是同一種習慣：**把「部分」講成「全部」。** 多問一句「它是不是只是某一種做法／某一種模型」，就少錯一半。

## 三句話記住整張表

如果連表都不想細看，記這三句就夠聊了：

```三分鐘速記版
一句話：LLM 就是「猜下一個詞」的機器。
三個坑：看得不多（窗口）、讀的是碎塊（token）、會亂講（幻覺）。
四招讓它有用：微調改行為、RAG 給證據、Agent 會動手、MCP 連工具。
```

> 最值得記住的一件事：這些名詞不是互不相干的魔法，而是環繞著同一個核心——「預測下一個詞」，再加「資料」與「工程」兩層。 你先有這張地圖，再逐詞往深處走，就不會迷路。

#### Q: 「把所有 token、RAG、Agent 都做好，就能造出 AGI」——這句話為什麼不對？

* 因為 AGI 只是「能同時做很多窄任務」的另一個名字

* 因為 token、RAG、Agent 都是工程技巧，而 AGI 是『通用智慧』的願景，今天的系統都還只是『窄』的

* 因為 AGI 根本不存在，這個詞是編的

* 因為 token、RAG、Agent 三種東西必須先合成一種東西

> 💡 token、RAG、Agent（以及微調、MCP）都是讓現有『窄 AI』更好用的工程手段；AGI 則是『什麼都能做』的通用智慧願景。工程技巧堆得多，也還沒有人把『窄』變成『通用』——這正是 intro-05 要講的爭議。
