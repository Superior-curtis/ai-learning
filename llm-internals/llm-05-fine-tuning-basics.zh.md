# 微調基礎

> 📅 2026-08-04 · 深入研究
> 微調到底改動了權重裡的什麼？LoRA 跟完整微調技術上有什麼差別？學習率、epoch、rank 各在控制什麼？這篇文章把微調的引擎蓋掀開。

---

「微調」這個詞，大家好像都懂，但要你說出「微調**到底改了權重裡的什麼**」，很多人會卡住。`train-02-finetuning` 講的是「該不該微調、微調能教會什麼」；這篇換個鏡頭，鑽進引擎蓋底下：**當你跑完一次微調，模型內部發生的事情可以用一句話概括——權重被輕輕移動了，語言統計的形狀被往你的資料方向推了一點。**

在注意力、嵌入、量化這些「內功」之後，微調是理解「模型如何被塑造成專才」的最後一塊拼圖。先講結論：微調不神祕。它跟預訓練用的是**同一套訓練引擎**，差別只在起點與資料。

## 同一套引擎，不同的目標

微調 = **在已經會講話的權重上，繼續跑「下一個詞預測」的訓練**，只是資料換成你的。

流程與預訓練完全一樣：

1. **forward**：模型對訓練樣本做預測，算出 loss（與正確的「下一個 token」差多少）。
2. **backward**：反向傳播，算出每個權重對這個誤差的貢獻——也就是梯度。
3. **update**：`W ← W − lr × 梯度`，把權重往「讓 loss 變小」的方向移一點。

跟預訓練唯一的不同：起點不是隨機權重，而是「已經內化了語言」的權重。所以微調的更新幅度小得多、需要的資料少得多、成本也低了好幾個數量級。

```python
# 概念：微調的每一次參數更新
# 1) forward：用目前權重做預測 → 算 loss
# 2) backward：算出每個權重對 loss 的貢獻（梯度）
# 3) update：W <- W - lr * gradient

lr = 1e-5   # 微調常用量級，比預訓練（約 1e-4）小一個數量級
epochs = 3  # 資料看幾遍；資料少就少看幾遍

# W 是某一層的權重矩陣。
# 完整微調：更新所有層的 W。
# LoRA：凍結 W，只訓練掛在旁邊的 A、B（見 finetune-02-lora）。
```

## 微調改變的，主要是「行為分布」而非「知識庫」

這裡是新手最大的誤區。很多人以為「微調 = 把新知識灌進模型」，但微調學到的絕大多數是**行為與分布的偏移**：

* **行為**：輸出格式、語氣、是否先道歉、是否用 JSON、聽不聽指令——這些「如何回應」的規則，微調最擅長。
* **知識**：要讓模型「記住一個新事實」，必須把這個事實**固定地**壓進某批權重裡。微調做得到，但極不划算、也容易淪為背誦。

回顧 `llmcore-01-next-token` 的心智模型：模型不過是把「哪個詞最順」的統計記在權重裡。微調改變的，正是這套統計的**形狀**——讓「你的領域裡的那些說法」在抽籤時更容易中籤。「知道一個事實」與「偏愛某種說法」，在權重層面是同一件事，只是前者比後者難得多。

> 記住這個分界：微調擅長改變「怎麼說」，不擅長可靠地灌輸「什麼是對的」。 需要隨時更新的新知識，那是上下文／RAG 的領域；微調是用固定資料把「說法」定型。

## LoRA 與完整微調：技術上的差別

「微調」這個詞底下有兩種截然不同的開銷。**完整微調（full fine-tuning）**更新全部參數；**LoRA** 凍結全部主權重，只訓練旁路的小矩陣。

```text
完整微調：                          LoRA：
更新全部權重 W                       凍結 W
W ← W − lr × 梯度                   只訓練旁路 A、B
輸出 = W + A × B
```

技術差別有四個層面：

| 層面 | 完整微調 | LoRA |
|---|---|---|
| 更新的參數 | 全部（7B 就是七十億個） | 只更新旁路 A、B（常不到 1%） |
| 記憶體 | 主權重 + 最佳化器狀態，動輒數倍權重 | 主權重凍結，只養 adapter |
| 表達力 | 不受限（更新是 full-rank） | 被 rank 限制在低秩空間 |
| 產物 | 一個全新的大權重檔 | 幾 MB 的 adapter |

用一句話概括：**LoRA 賭的是「你需要的改動，其實住在一個很小的低秩空間裡」**——不是每次都成立，但實務上常常成立。想省記憶體與檔案大小，LoRA 幾乎是預設選項；只有在改動幅度真的很大、低秩空間裝不下時，完整微調才明顯值得。

## 超參數：學習率、epoch、rank

微調的品質，很大程度由三個旋鈕決定：

| 超參數 | 控制什麼 | 常見陷阱 |
|---|---|---|
| **學習率（lr）** | 每一步把權重移動多大 | 太高 → 爆掉、遺忘原有能力；太低 → 學不動 |
| **epoch** | 資料被看幾遍 | 太多 → 過擬合（背下資料，不會泛化） |
| **rank（LoRA）** | 旁路的寬度 | 太大 → adapter 變胖、收益遞減；太小 → 學不夠 |

幾個實務量級：

* **學習率**：微調常用 `1e-5` 這個等級，比預訓練（約 `1e-4`）小一個數量級。起點已經很好，步幅必須小，才不會把原本的語言能力踩壞。
* **epoch**：微調資料通常不多，看個 2～3 遍就夠。資料越少，越要小心過擬合——留一份沒參與訓練的驗證集來觀察。
* **rank**：先從 `r = 8～32` 起步，效果不夠再往上加。

## 一次微調的真實經歷

把畫面切到 GPU 上，跑一次小規模微調大概是這樣：

1. 你把幾百條「輸入 → 期望輸出」的樣本餵進去。
2. 每個 batch，模型做出預測、算 loss，然後把權重往正確方向推一點點。
3. 隨著時間，**訓練集的 loss 穩定下降**——模型開始「背住」你資料裡的規律。
4. 同時，權重以肉眼不可見的速度緩慢漂移。你以為它在「學新東西」，其實更像「天平被一點一點撥向你的說法」。

到這裡你可能會問：那到底什麼時候該停？答案跟下一個概念綁在一起。

## 過擬合：微調的頭號敵人

過擬合是「背資料」與「學會規律」之間的分水嶺：

| 訊號 | 健康 | 過擬合 |
|---|---|---|
| 訓練 loss | 持續下降 | 降到趨近 0 |
| 驗證 loss | 跟著下降 | **回升**（背誦開始、泛化崩壞） |
| 輸出表現 | 穩定、可泛化 | 只對訓練樣本完美，換個說法就破功 |

防護招式很樸素：**留驗證集、epoch 不要貪、必要時早期停止、資料少而乾淨。** 這些在 `finetune-02-lora` 的實務篇會具體展開；這裡只要記住方向——「學得久」不等於「學得好」。

還有一個更根本的防護：資料品質。幾百條乾淨、一致、標註正確的樣本，勝過幾千條格式混亂的資料——髒資料會被模型「學進去」，上線後以更怪異的方式還給你。

## 行為 vs 知識：一個具體的例子

假設你想讓模型模仿你家客服的語氣。微調後發生的事是：在「請提供您的要求」這類句子後面，模型給「我們會盡快為您處理」的分數明顯變高——**抽籤的天平偏了**。而模型的「世界知識」幾乎沒動：它還是不知道你們公司今天有沒有庫存（那是 RAG 的題）。

這就是為什麼「微調讓模型變專精」與「微調讓模型變聰明」是兩件不同的事——前者靠移動分布的形狀，後者則困難得多。

這也解釋了為什麼微調 demo 特別容易騙到自己：拿訓練樣本去展示，看起來神乎其技——因為那正是模型剛背下的樣本。要用沒參與訓練的樣本來判斷效果。

## 一張表帶走

| 概念 | 一句話 |
|---|---|
| 微調 | 用你的資料，在已會講話的權重上繼續跑「下一詞預測」訓練 |
| 學到什麼 | 主要是行為與分布偏移（怎麼說），不是可靠的新知識 |
| 完整微調 | 更新全部參數；貴、表達力高 |
| LoRA | 凍結主權重，只訓練低秩旁路；省、檔案小 |
| 學習率 | 步幅大小，微調常用 1e-5 等級 |
| epoch / rank | 看幾遍資料 / 旁路寬度；兩者過大都會往過擬合靠 |

## 那什麼時候該動真格

這篇講的是原理。要不要微調、該怎麼判斷——是 `train-02-finetuning` 的事；真正動手、把成本壓下來——是 `finetune-02-lora` 的事。這篇給你的是一雙看穿「微調神祕感」的眼睛：**它只是用梯度下降，把語言統計的形狀，往你的資料方向再推一點。** 帶著這雙眼睛回去看任何一篇「微調實戰教學」，你都能看懂每一步在做什麼——改的從來不是「記憶」，而是「分布的形狀」。

#### Q: 「微調讓模型記住公司最新的產品知識」這個期待，為什麼常常落空？

* 微調完全不會改變模型

* 微調擅長改變「怎麼說」（行為與分布），但可靠地灌輸新事實成本高、易淪為背誦

* 微調只會讓模型變笨

* 最新的產品知識只能靠預訓練學到

> 💡 微調改變的是權重裡「哪種說法更順」的統計形狀。行為、格式、語氣學得又快又好；但新事實要固定壓進權重、又容易變成背誦，通常交給上下文或 RAG 更划算。
