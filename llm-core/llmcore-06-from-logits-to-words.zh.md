# 從分數到文字：解碼全流程

> 📅 2026-08-04 · 核心概念
> 模型不會「開口說話」——它只是不停跑同一個小迴圈：把上下文算成分數、抽一個詞、接回去、再算一次。這篇文章把解碼流程從頭到尾走一遍，為 llm-core 系列收尾。

---

前五篇文章，我們把 LLM 拆成了零件：token（`llmcore-02-tokens`）、上下文窗口（`llmcore-03-context`）、抽樣（`llmcore-04-sampling`）、幻覺（`llmcore-05-hallucination`），而一切的起點是「預測下一個詞」（`llmcore-01-next-token`）。現在把零件裝回去，看整台機器實際運轉：從你按下送出，到螢幕上開始跳出文字——**中間到底發生什麼事？**

答案是**解碼（decoding）**，一套比你想像中樸素得多的流程。模型不會「開口說話」，它只是不停跑同一個小迴圈：**看看目前的上下文、算一次分數、抽一個 token、接回去、再算一次。**

## 整條迴圈，一眼看完

```text
tokenizer 把輸入切成 token
↓
[ 上下文 ]  ← 系統提示 + 訊息 + 歷史 + 已生成的 token
↓
forward pass：對字典裡每個 token 打一個分數（logits）
↓
softmax → 機率分布
↓
抽樣抽中一個 token（llmcore-04-sampling）
↓
把 token 接回上下文尾端，窗口長長一格
↓
（迴圈）再預測下一個 token ……
```

每跑一圈，輸出一個 token。一段 500 字的回覆，就是這條迴圈默默跑了幾百次。分開看每一步都很無聊，合起來卻能寫出整篇文章——奧祕就在「迴圈」本身。

## 第一步：token 進場

在模型動手之前，輸入要先被 tokenizer 切成 token（`llmcore-02-tokens`）。然後，系統提示、使用者訊息、到目前為止的對話——**全部**都要塞進上下文窗口（`llmcore-03-context`）。窗口有多大，模型這一輪就能看多遠；窗口外的內容，等同於不存在。

有一個容易被忽略的事實：模型「看」的是這串 token 的**一次快照**。每次迴圈，它都把目前為止的整個上下文**重新讀一遍**——不是「記得」，是重看。

## 第二步：一次 forward pass，吐出 logits

模型把這串 token 推過它的幾十層網路——這叫**一次 forward pass**。輸出的是一個長長的清單：**字典裡每一個 token，都有一個分數**，這些原始分數叫做 **logits**。

* 分數越高，代表「模型認為它越適合接在後面」。
* logits 是原始分數，不是機率——可正可負、大小不設限。

這一步是整個迴圈裡唯一真正的「計算」。Transformer 本質上就是一個大函數：**把一串 token 對應到一組分數。** 換句話說，前面幾篇看到的「知識」「理解」，到頭來都是藏在這個函數的參數裡。

## 第三步：抽樣決定「誰勝出」

logits 還不能直接用。先把分數經過 `softmax` 變成機率（總和為 1），然後**按機率抽一個 token**——這一步就是 `llmcore-04-sampling` 講的抽籤。

* 溫度、top-p、top-k 都在這一步作用。
* 抽中誰，誰就是「本輪的輸出」。

同一個問題問兩次答案不同，就是因為這一籤。想讓輸出更確定？把溫度調低、把低機率詞篩掉，都在這一步發生。

## 第四步：接回去，再來一次

被抽中的 token 會被**接回上下文尾端**，形成一個「長了一點點」的新上下文。然後迴圈回到第二步：拿這個新上下文，再算一次分數、再抽一個。

因為模型「把自己的輸出當輸入」，它被稱為**自迴歸（auto-regressive）**——這是整個生成機制最核心的關鍵字。迴圈不會無止境跑下去：當模型抽到代表「結束」的特殊 token（EOS），或觸及長度上限，生成就停了。

## 為什麼看起來像「寫作」

把這個迴圈拆開，每一步都極度機械。但合成的效果卻非常流暢，關鍵在於：**每一步都能看到前一步才剛寫下的內容。** 當模型寫出「巴黎」後，下一輪它已經知道文章裡出現過「巴黎」，於是能接著寫「的塞納河」。一詞接一詞，「記得自己寫過什麼」不是靠什麼額外記憶體，而是靠迴圈自然達成的。

這也解釋了 `llmcore-05-hallucination` 的另一面：迴圈只在乎「下一個詞順不順」，所以它可以寫出結構完美、內容全錯的段落——因為迴圈根本不檢查事實。

## 一次只吐一個 token 的代價

迴圈一次只吐一個 token，這個「一次一個」的約束，決定了使用體驗的三件事：

* **速度**：每輸出一個 token，都要重新跑一次完整的 forward pass。輸出越長，等待越久——這正是 `llmcore-02-tokens` 說「輸出越少 token，回覆越快」的原因。
* **成本**：每個輸出的 token 都要計費。長回覆 = 貴回覆，這是 API 帳單上最直接的事實。
* **無法回頭**：一般的解碼流程裡，token 一旦被抽中就被固定下來，模型不會回去改寫。它只能靠「之後的 token」把話圓回來——這既是連貫文章的來源，也是邏輯破洞與幻覺的溫床。

## 三個實務生成策略

同一個迴圈，配上不同的抽樣旋鈕（`llmcore-04-sampling`），就是三種性格的產品：

| 策略 | 做法 | 適合 |
|---|---|---|
| **貪婪（greedy）** | 每次選最高分，不抽籤 | 摘要、翻譯、需要確定性的任務 |
| **低溫抽樣** | 抽籤，但幾乎只抽高分 | 一般對話、程式碼生成 |
| **高溫抽樣** | 低分詞也有機會中籤 | 寫作、點子發想、放鬆語氣 |

旋鈕不改迴圈本身——改的只是「第三步的抽籤規則」。所以同一個模型可以是工程師，也可以是詩人，端看你給它哪組參數。

## 記住這一句

> 模型生成文字，不是「想好再講」，而是每步只看目前上下文、算一次分數、抽一個 token、接回去。一切看起來的「理解」與「知識」，都只是這條迴圈內的統計結果。

## 用一段概念程式碼收攏

真實的解碼發生在 GPU 上的矩陣運算裡，但骨架可以寫成幾行。注意中間那顆「抽籤」——它把確定性的分數，變成了一次性的選擇：

```python
# 概念示範：解碼迴圈的一步（真正的模型是 GPU 上的矩陣運算）
import math, random

# Step 1 — 目前為止的上下文（一串 token）
context = ["The", "cat", "sat"]

# Step 2 — forward pass：對字典裡每個 token 打一個分數（logits）
logits = {"on": 3.2, "in": 2.1, "down": 1.0, "under": 0.7}

def softmax(scores):
  exp = {t: math.exp(s) for t, s in scores.items()}
  total = sum(exp.values())
  return {t: e / total for t, e in exp.items()}

# Step 3 — softmax 把分數變成機率
probs = softmax(logits)

# Step 4 — 抽樣：按機率抽一個 token（旋鈕見 llmcore-04-sampling）
next_token = random.choices(list(probs), weights=probs.values(), k=1)[0]

# Step 5 — 接回去，更新上下文，然後迴圈回到 Step 2
context.append(next_token)
# 抽到「結束」token 或到長度上限 → 迴圈停止
```

## 把整個流程縮成四步

如果要用四個詞帶走這篇文章：

#### Token 進場

輸入被 tokenizer 切好，塞進上下文窗口（見 llmcore-02-tokens、llmcore-03-context）。

#### 算分數

一次 forward pass，對字典裡每個 token 給一個 logits。

#### 抽一個

softmax 變機率，按抽樣策略抽中一個 token（見 llmcore-04-sampling）。

#### 接回去，再來

token 接回上下文；未遇到「結束」符號就回到第二步。

## 一張表，把系列串起來

| 零件 | 文章 | 在迴圈裡的角色 |
|---|---|---|
| token | `llmcore-02-tokens` | 迴圈處理的基本單位，也是計費單位 |
| 上下文 | `llmcore-03-context` | 每次 forward pass 看到的輸入快照 |
| logits | 本篇 | 模型給每個候選 token 的原始分數 |
| 抽樣 | `llmcore-04-sampling` | 決定抽哪一個，控制穩定與創意 |
| 幻覺 | `llmcore-05-hallucination` | 迴圈抽得很順、但事實錯了 |

#### Q: 「自迴歸（auto-regressive）」裡的「迴歸」，指的是什麼？

* 模型會反覆修改同一個句子直到滿意

* 模型把自己的輸出接回上下文，再預測下一個 token

* 模型回頭搜尋網路上相似的句子

* 模型在訓練時重複同一批資料

> 💡 迴歸指的是「把輸出當輸入」：抽中的 token 被接回上下文，成為下一步 forward pass 的輸入，如此循環直到抽到結束 token 或達長度上限。
