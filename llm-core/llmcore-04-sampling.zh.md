# 抽樣與溫度：怎麼「猜」是可以調的

> 📅 2026-08-04 · 核心概念
> 同一個問題問兩次，答案為什麼不同？因為模型是「抽籤」，不是「選答案」。溫度、top-p、top-k 三個旋鈕，決定它是保守還是天馬行空。

---

回顧 `llmcore-01`：模型對每個候選詞算一個機率分布，然後「抽」一個詞。這篇文章拆開「抽」這個動作——因為**從分布裡怎麼抽，是可以調的**，而這三個旋鈕（溫度、top-p、top-k）決定了 AI 的回答是保守、穩定，還是創意、跳tone。

## 抽籤 vs 選答案

先建立對比。模型拿到機率分布之後，有兩種極端的做法：

| 做法 | 行為 | 後果 |
|---|---|---|
| **貪婪（greedy）** | 每次都選機率最高的詞 | 穩定、可重複，但死板、容易繞圈 |
| **抽樣（sampling）** | 按機率抽籤 | 多樣、自然，但每次可能不同 |

真實產品大多介於中間：**用抽樣，但用旋鈕控制「抽得多野」**。這就是為什麼同一個問題問兩次，答案往往不一樣——不是壞掉，是抽籤的結果不同。

## 溫度（temperature）：把分布變尖或變平

溫度是最有名的旋鈕。它不改機率排名，只改「差距」：

* **溫度低（接近 0）**：把「高機率的詞」與「低機率的詞」的差距**拉大**，幾乎等於選最高分的詞 → 保守、確定、像在念稿。
* **溫度高（例如 1.5+）**：把差距**壓平**，低機率的詞也有機會中籤 → 創意、跳tone、偶爾胡言亂語。
* **溫度 = 1**：原樣抽籤，不做調整。

概念上，溫度是拿機率分布「開根號」：根號會把大的變小、小的變大（相對來說）。

```text
原始分布          溫度低（0.2）      溫度高（1.5）
fast 42%          fast 88%          fast 30%
quickly 31%       quickly 11%       quickly 27%
forward 11%       forward 1%        forward 19%
其他 16%          其他 0%           其他 24%
（比較平均）      （幾乎選定 fast）   （誰都可能中）
```

> 記住精神：溫度控制「預測的賭性」。 想要事實、程式碼、確定答案 → 低溫；想要寫故事、想點子、放鬆語氣 → 高溫。很多產品用 0 ～ 1 的範圍，1 以上就開始「漂」。

## top-p 與 top-k：只給高分詞參賽資格

溫度會讓「機率低的詞」偶爾中籤，但有時這太危險（例如打錯一個 API 名）。所以有另外兩個旋鈕，直接**篩掉低分詞**：

* **top-k**：只留機率最高的 k 個詞，其餘淘汰。例如 top-k=10 → 只看前 10 名，剩下的都不准抽。
* **top-p（nucleus，核心抽樣）**：從機率最高的詞開始，一路往下加，直到累計機率超過 p（例如 0.9）。也就是「保留佔了 90% 機率的這群詞」，把長尾巴砍掉。

兩者可以疊加：先 top-k 砍到剩 10 個，再 top-p 砍掉那 10 個裡的尾巴。

```概念的抽樣實作
import random

logits = {"fast": 2.1, "quickly": 1.7, "forward": 0.9}
# 1) softmax → 機率
probs = {"fast": 0.42, "quickly": 0.31, "forward": 0.27}

# 2) temperature：分數 ÷ 溫度（temp 越低，差距越大）
# 3) top-k：只留機率最高的 k 個
# 4) 抽籤
picked = random.choices(list(probs), weights=probs.values(), k=1)[0]

# 商業模型 API 直接傳參數即可：
#  temperature=0.2, top_p=0.9, top_k=40
```

## 三個旋鈕怎麼搭配：一張決策表

| 用途 | 溫度 | top-p / top-k |
|---|---|---|
| 翻譯、程式碼、數學 | 低（0～0.3） | 開（保守，怕錯字） |
| 一般對話、摘要 | 中（0.7） | 可關或設高（0.9） |
| 寫作、腦力激盪 | 高（0.9～1.3） | 關（讓低機率詞有機會） |

> 實務鐵律：先想「這任務要確定還是要有創意」，再決定溫度。 讓程式碼生成去跑高溫抽樣，是免費獲得靈感（以及超難抓的 bug）的捷徑。

## 為什麼產品「看起來穩定」

你可能會問：那為什麼 ChatGPT 這種產品看起來每次都差不多？

因為產品會做兩件事：

1. **把溫度調低**——預設偏保守。
2. **系統提示限定**——用指令把輸出框死（格式、語氣）。

所以「產品穩定」是「低溫 + 強提示」的結果，不是模型天生穩定。想更可控，就降溫、寫清楚的輸出規格。

## 回到最初的問題

「為什麼同一個問題問兩次答案不同？」

* 因為產品在抽樣（不是貪婪）。
* 溫度越高，差異越大；溫度接近 0，差異趨近於零。
* 如果一定要完全一致，把溫度設 0 即可（不少 API 也支援）。

理解了「抽」的旋鈕，下一步自然要面對它的黑暗面：當模型**很自信地抽錯**時，就叫做幻覺（`llmcore-05-hallucination`）。

#### Q: 想要「程式碼生成盡可能穩定正確」，你該怎麼調參數？

* 把溫度調高，讓輸出更有創意

* 把溫度調低，並考慮用 top-k / top-p 篩掉低機率詞

* 把 top-p 調到最低，讓更多詞進得了名單

* 關掉抽樣改貪婪就好，參數都無所謂

> 💡 程式碼講求正確與可重複：低溫把差距拉大（趨近貪婪），top-k/top-p 再砍掉低機率詞，雙重壓制出錯。高溫只會引入隨機錯字與幻想 API。
