# 上下文窗口：模型能看到多遠

> 📅 2026-08-04 · 核心概念
> 模型沒有記憶——它只有一次能同時看到的 token 上限，叫做上下文窗口。這決定了一場對話、一份文件能塞多大。

---

很多人以為聊天機器人「記得」你說過的話。其實**模型沒有記憶**——它只是在這次對話的「視窗」裡，每次都重看一遍目前為止的所有內容。這個「一次能看多少」的上限，叫**上下文窗口（context window）**。

它是最實際、最直接影響你使用體驗的概念之一：決定了你能貼多長的文件、聊多久的對話、以及「它到底記不記得三小時前你講的那句話」。

## 上下文窗口是什麼

上下文窗口 = 模型一次能「同時看到」的 token 數量上限。

* 8K 上下文 → 每次最多能看到約 8,000 個 token（你貼的文章 + 歷史對話）。
* 200K 上下文 → 可以塞進一本幾百頁的書。

關鍵在「**同時**」：模型每次生成時，把窗口裡**所有的 token** 一起拿來參考，然後預測下一個詞。窗口外的內容，模型就像從沒看過一樣。

```text
[系統提示][使用者文章][歷史對話]…[剛剛生成的詞] ← 都要塞進這個窗口
│                                                                                                    │
└─────────────── 一次最多 = 上下文窗口大小（例如 200K token）────────────────────┘
窗口提早塞滿 → 最「舊」的內容會被擠掉（或需要你手動清理）
```

## 一個最容易誤解的點：模型「不記得」

你以為的「記憶」，其實是兩個不同機制的混合：

| 你以為 | 實際 |
|---|---|
| 模型記得整段對話 | 每次都把整段對話重看一遍（在窗口內） |
| 模型記得昨天你教它的偏好 | **沒有**。今天開新對話，它從零開始 |
| 模型看過你貼的 PDF | 只在「那一次」的窗口內有效 |

> 一句話記住：模型是「重看」，不是「記憶」。 你每傳一句話，它都把窗口翻到底再想一次。窗口一切換（新對話／超過上限），舊內容就消失。真正的「記憶」是靠外部儲存，不是靠模型。

## 上下文 vs 長期記憶

既然模型會「忘掉」，真正的長期記憶是怎麼做的？用**外部工具**把過去內容放回窗口：

* 把重要事實存到資料庫或檔案。
* 新對話時，把相關片段「貼回」窗口。

這正是 **RAG（檢索增強生成）** 在做的事——它不是給模型裝記憶，而是**每次需要時，把正確的舊內容重新搬進窗口**。詳見 `llm-03-rag`。所以：

> 上下文窗口 = 模型的「工作記憶」；RAG / 檔案 = 模型的「長期記憶」；兩者常被混淆。

## 為什麼窗口會有上限

不是做不出無限窗口，而是**代價太大**。

注意力機制讓每個 token 都要「參考」其他所有 token——token 數一多，計算量急速成長。此外，你每次多丟進窗口一張 paper，模型要讀、要計費，成本跟著漲。

```窗口與成本的精神（概念）
# 注意力讓每個 token 看其他所有 token → 計算隨長度變貴
# 這是以 token 計費的另一個落點：輸入越多，成本越高

# 你每輪都會把"整段對話"重新送出去一次：
messages = [
  {"role": "user", "content": "第一篇長文章（8000 tokens）"},
  {"role": "assistant", "content": "第一篇回覆（500 tokens）"},
  {"role": "user", "content": "第二篇長文章（8000 tokens）"},
]
# 這輪光是輸入就超過 16K tokens
```

因此工程上常有取捨：

* **長上下文模型**：能讀大文件，但較貴、較慢。
* **短上下文模型**：便宜、快速，但塞不下長文——需要你「摘要後再餵」。

## 善用有限的窗口：幾個實務心法

**1. 最重要的放最前面 / 最後面。** 模型對開頭（系統提示）與結尾（最近的指令）往往最敏感，中間內容容易被稀釋。

**2. 摘要，而不是堆疊。** 長對話到中段，把前面濃縮成一兩段摘要塞回去，別把原文一路累積到爆。

**3. 只餵需要的。** 與其貼一整份 100 頁的書，不如用 RAG 先把相關的幾段撈出來再餵。

**4. 分段處理大型文件。** 超過窗口就切成好幾段，分批問，再統整。

## 「把知識塞進窗口」vs「改模型」

這是 AI 圈最重要的二選一之一，值得現在就建立直覺：

| 做法 | 改變的是 | 何時用 |
|---|---|---|
| **上下文**：把知識放在提示裡 | 每次的輸入 | 隨時、靈活、不需重新訓練 |
| **微調**：把知識寫進模型權重 | 模型本身 | 學固定技能／風格，代價高 |

對「要不要讓模型懂我家公司的產品文件」這種問題，**九成先用上下文／RAG**，別急著微調。詳見 `finetune-01-finetune-vs-rag`。

## 所以「記憶」怎麼用

現在你建立了正確心智模型：

* 模型的「眼睛」= 上下文窗口，一次看清楚多遠，有上限。
* 模型的「舌頭」= 每次只吐一個 token，再接再厲地吐下一句。
* 窗口外的世界、窗割之間的過去——模型都「不在場」。

下一篇，看看「猜下一個詞」那張機率籤，是可以調冷熱的：`llmcore-04-sampling`。

#### Q: 為什麼「模型記得我昨天教它的偏好」這個印象是錯的？

* 模型有記憶，只是容量很小

* 模型每次都在窗口內重看目前對話，新對話從零開始，沒有跨對話記憶

* 只有付費版才有記憶

* 模型把偏好存到雲端，但會過期

> 💡 模型是無狀態的：它只看得到當次窗口內的內容，並重看。跨對話的「記憶」必須靠外部儲存（如 RAG/檔案）在需要時把內容搬回窗口。
