# 商業模式

> 📅 2026-08-04 · 核心概念
> AI 公司到底靠什麼賺錢？按 token 計價、SaaS 包裝、賣產品或代理、開放權重加服務——以及最殘酷的單元經濟學：帳單算不算得過來。

---

把價值鏈（`industry-01-value-chain`）和玩家（`industry-02-players`）記住之後，只剩一個務實問題：**這門生意到底怎麼收錢？**

答案不是一句話，而是幾種模式的組合。每一種都有自己的計價邏輯、客戶和死穴。這篇把主流的五種擺上桌，最後算一筆「燒錢 vs 營收」的現實帳。

## 模式一：按 token 計價的 API

最直覺的模式：**用多少，付多少。** 模型的單位不是「每小時」，而是「每 1,000 個 token」（約等於幾百個字）。

```text
輸入 token（你送進去的話）→ 輸出 token（模型吐出來的話）
            ↓ 每個都計價
呼叫一次 = 輸入價 × 用量 + 輸出價 × 用量
```

* **對誰好用**：開發者。成本可預測、無需自備 GPU、隨時擴縮（規模從 0 到百萬用戶）。
* **對誰難受**：用到很大量的公司。長文件、代理迴圈、大批量任務，帳單會隨用量線性成長。
* **商業邏輯**：賣的是「推理」這件商品——所以推理成本就是毛利的分母，詳見 `econ-01-inference-cost`。

## 模式二：SaaS 包裝

把模型包進「你本來就熟悉」的產品外殼：文件、試算表、客服後台、寫作工具。用戶不買 token，買**「每個月一筆固定費用」**。

* **定價優勢**：可預測的訂閱費，而不是浮動的用量帳單。
* **留存優勢**：用戶為「解決問題的流程」付費，不只是為模型付費——換模型不像換供應商那麼容易。
* **風險**：包裝得太薄，用戶隨時可以自己接 API 抄掉你；包裝得夠厚（流程、資料、整合），才有護城河。

## 模式三：應用與代理產品

不只是「包裝」，而是**直接替用戶做完一件事**：自動客服、自動寫報告、自動操作軟體（agent，見 `agents-01-what-is-agent`）。

* 計價常從「按結果」出發：完成一件任務、處理一張單據、關閉一張工單。
* 它比「按 token」更能讓客戶買單——客戶付的是「這件事的價值」，不是「背後的算力」。
* 但成本藏在看不見的地方：一個 agent 任務可能呼叫十幾次模型，成本是「一次回答」的十幾倍。毛利被推理成本吃掉，是這個模式最常見的翻車點。

## 模式四：開放權重 + 服務

自己不煉模型，而是**站在開放權重（Llama、Qwen、DeepSeek）之上，賣「部署 + 維運 + 客製 + 顧問」**。

* 客戶買的是「在自己的伺服器上安全跑模型」的整套服務，常見於醫療、金融、政府等敏感場景（呼應 `models-01-open-vs-closed`）。
* 收入來自專案費、年費、人力費，而非按量計價——單價高，但毛利結構更像傳統軟體服務業。

## 五種模式一覽

| 模式 | 賣什麼 | 怎麼收費 | 主要風險 |
|---|---|---|---|
| **Token API** | 推理能力 | 按用量 | 推理成本壓縮毛利、客戶做大後自架 |
| **SaaS 包裝** | 解決問題的產品 | 月費/年費 | 包裝太薄被 API 繞過 |
| **應用 / 代理** | 做完一件事的結果 | 按任務/結果 | 多次呼叫讓成本爆炸 |
| **開放權重 + 服務** | 自架整套方案 | 專案/年費/人天 | 規模化困難、人力密集 |
| **廣告 / 流量（輔助）** | 免費 AI 聚流量 | 廣告或生態導流 | 不直接賣 AI，毛利靠別處 |

## 殘酷的單元經濟學：燒錢 vs 營收

所有模式的共同分母，是一張**「每一次交付，我賺不賺」**的帳：

```text
毛利 = 售價 - 交付成本
交付成本 ≈ 推理成本 + 獲客成本 + 支援成本

營收大，不等於賺錢：
  賣出一百萬次「一次回答」，
  但每次推理成本吃掉售價的一半以上 → 規模越大虧越多
```

* **實驗室的處境**：訓練（`train-01-pretraining`）與推理都極貴，需要靠大量 API 收入攤平；許多「營收成長」其實以燒錢為代價。
* **應用的處境**：營收成長快，但只要「賣一元的 AI 功能要花超過一元的推理與獲客」，就是越快越虧。
* **健康的信號**：不是營收，而是**「每單位毛利」和「客戶留存」**——用戶留下來重複使用，才代表付費買到的東西真的值。

> 要記住的一件事：AI 生意的成敗不只看營收成長，而是看「每一元營收背後的交付成本」——尤其是推理成本（econ-01-inference-cost）。毛利為正、客戶留得住的成長，才是真成長。

## 把數字算給你看：一個 agent 的單元帳

抽象說「成本會吃掉毛利」，不如算一筆具體的。假設輸入每百萬 token 3 元、輸出每百萬 15 元（量級接近真實市場），一個「自動客服」agent 完成一張工單要呼叫四次模型：

```概念：一次任務的推理成本
# 輸入 $3 / 1M token，輸出 $15 / 1M token
# 自動客服完成一張工單 = 4 次模型呼叫

步驟          輸入    輸出    成本($)
1. 理解工單    0.5K   0.1K   0.003
2. 查詢系統    0.6K   0.3K   0.006
3. 起草回覆    1.0K   0.2K   0.006
4. 摘要存檔    0.8K   0.1K   0.004
──────────────────────────────────
合計           2.9K   0.7K   0.019

→ 一張工單的推理成本 ≈ $0.02
售價 $0.05 → 毛利 60%
售價 $0.01 → 每單虧 $0.01，越做越虧
```

看懂這張帳，就懂為什麼「按結果計價」的 agent 產品特別危險：**客戶覺得自己買的是「一件完成的任務」，但你的成本是「任務背後 N 次模型呼叫」。** 任務越複雜、工具越多、重試越多，單元成本就越失控。

## 定價戰：模型們在賽跑降價

另一個正在發生的動態，是**定價本身也在被當作武器**。

* 新模型發布往往同時「更強 + 更便宜」，用降價搶市佔。
* 開放權重（`models-01-open-vs-closed`）把「價格下限」壓到近乎零——自架時你只付算力成本。
* 結果是：**Token 的單價在下降，但用量在暴漲。** 對實驗室是「薄利多銷」的賭注；對應用層，則是把「推理成本」這個分母越做越大。

這把尺子最後都會連到同一個問題：一次回答的成本到底怎麼算——`econ-01-inference-cost`。

## 規模決定打法：同一條鏈，不同玩法

同樣面對這五種模式，不同規模的玩家會做完全不同的選擇。用「規模」當座標，可以看出策略的規律：

| 玩家規模 | 典型模式 | 理由 |
|---|---|---|
| **個人 / 小團隊** | Token API 起步 | 零前期成本、隨用量成長，驗證需求最便宜 |
| **成長中的新創** | Token API + SaaS 包裝 | 先證明付費意願，再談鎖定 |
| **中型產品公司** | 自架開放權重 + 服務 | 用量大到計費嚇人時，換算自架成本 |
| **大型企業** | 混用：API + 自架 + 私有資料 | 敏感與非敏感分流，風險與成本平衡 |
| **平台巨頭** | 全鏈整合 | 同時握模型、算力與分發 |

一條實用的準則：**「用量小到可預測」用 API；「用量大到綁定毛利」考慮自架；「到了巨頭規模」就不只是選模式，而是建生態。**

## 整合趨勢：薄層正在被夾擊

最後看大局。這幾種模式正在被兩個力量擠壓：

1. **上游向下整合**：雲端與實驗室直接把「模型 + API + 平台」捆好賣，中間的薄層中介（只轉售 API 的那種）被夾扁。
2. **下游向上併購**：有場景、有資料的應用公司，被資本或大廠買下，好把「模型」跟「分發」縫在一起。

結果是「**要嘛有不可取代的場景與資料，要嘛有規模化的基礎設施**」——中間地帶正在消失。這也解釋了為什麼我們看到一波波「併購與結盟」的新聞：大家在搶的不是模型，是**位置**。

## 下一步

產業、玩家、商業模式都看完了。接下來把鏡頭轉向最硬的數字：**一次回答到底要花多少錢，又是什麼決定了它**——`econ-01-inference-cost`。

#### Q: 為什麼「按 token 計價的 API」生意，看似營收成長很快，卻不一定賺錢？

* 因為 token 計價太貴沒人買

* 因為每一次交付都背著推理成本，售價與成本之間的毛利才是關鍵，營收大不代表毛利為正

* 因為 API 生意不能規模化

* 因為用戶從來不付錢

> 💡 營收等於售價乘以用量，但每一次交付都要付出推理、獲客與支援成本。如果每賣一元要花超過一元的交付成本，規模越大反而虧越多——所以要看毛利與留存，而不是只看營收。
