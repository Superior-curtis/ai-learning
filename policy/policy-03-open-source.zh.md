# 開源與監管的張力：可審計的透明，還是管不住的模型？

> 📅 2026-08-04 · 深入研究
> 開放權重讓任何人都能審計模型，也讓任何地方都能跑出「沒人管」的模型——同一件事，兩種解讀。這篇把雙方論點、監管可能的樣子、與辯論現況都擺上桌，不替你選邊。

---

一家實驗室把模型權重公開放上網路。一個人看到的是「世界上最透明的釋出」——全世界每個安全研究員都可以檢查它。另一個人看到的是「再也關不上的閘門」——權重一旦公開，實驗室就再也控制不了誰在跑它、在哪裡跑、拿來做什麼。**兩種解讀描述的是同一個動作。** 整場辯論的關鍵，就是你從哪一個解讀出發。

這篇把兩邊的論點、監管可能動用的工具、與辯論現在站在哪裡，一起擺上桌。

## 先確認：開放權重到底是什麼

`models-01-open-vs-closed` 已經講過完整的光譜，這裡只記兩件事：

1. **開放權重（open-weight）** 指的是你可以下載訓練好的模型數值，自行部署、微調；它不必然等於「開放原始碼」——訓練資料與訓練流程常常不公開。
2. 對監管而言，最關鍵的物理事實是：**一個下載下來的權重，是一份「複本」**——可以被無限複製、隨時隨地低成本運行，而且無法「下架」。

一份權重一旦進入幾千人的硬碟，再強大的政府也無法把它收回去。這是後面所有張力的起點。

## 開放陣營的論點：安全靠透明

主張開放權重的一方，理由不是「免費」，而是「安全」：

* **透明讓安全研究成真**：開放權重讓任何人可以獨立審計、紅隊測試、重現實驗室的聲明。封閉實驗室說「我們測過了」，開放權重讓全世界可以驗證「真的測過了」。
* **分散降低集中風險**：能力不要集中在少數公司手裡，就沒有單一的控制點、也沒有單一的故障點。去中心化本身是對「權力集中」的制衡。
* **生態系跑得更快**：微調、領域適應、本地部署、教學，都靠「拿到權重」才做得起來；封閉 API 永遠追不上這種開放創新的速度。
* **封閉系統也防不了濫用**：API 可以被越獄，權重可以被竊取。與其假裝封閉能鎖住一切，不如讓威脅在陽光下可見。

## 封閉陣營的論點：安全靠控制

主張嚴格控管權重釋出的一方，不是反對開放，而是怕它的後果：

* **釋出不可逆**：軟體漏洞可以打補丁，權重不行——那是一張快照。公開之後，你無法召回、無法更新每一份複本。
* **前緣風險**：最強的模型若被用於生物武器、網路攻擊等場景，受控的部署與使用監測，是唯一有效的閘門。
* **護欄是「服務」的屬性，不是「檔案」的屬性**：對齊、安全過濾、使用紀錄，都是線上服務才有的東西；一個下載到本地跑的權重，什麼護欄都沒有。
* **「自由」的背面是「免責」**：如果每個人都能用最強權重無限量製造內容，辨別真偽的成本會攤到整個社會身上。

#### 對照 / Comparison

## 兩邊其實在吵同一件事

把兩邊的論點對照著看，會發現它們在「安全從哪裡來」這個問題上完全相反：

| 面向 | 開放陣營的看法 | 封閉陣營的看法 |
|---|---|---|
| 安全的來源 | 透明：越多眼睛看越安全 | 控制：釋出越受限越安全 |
| 對釋出的態度 | 釋出是加速器，生態靠它起飛 | 釋出不可逆，是風險的源頭 |
| 對集中的看法 | 分散是對權力的制衡 | 受控的集中能守住前緣風險 |
| 最大的疑慮 | 權力壟斷、封閉系統被越獄 | 無法追回、權重護欄全部失效 |

兩邊其實都同意「開放權重很有力量」，分歧在於：**這股力量該不該被設閘。**

## 兩個真實的釋出時刻

把抽象辯論拉回具體事件，兩次釋出最能說明張力：

* **Llama 系列的分階段釋出**：Meta 起初要求使用者申請、審核後才給權重（俗稱「白名單」制），後來才全面開放下載。支持者說這是「負責任釋出」的範例；批評者說，審核擋不住真想濫用的人，只會拖慢研究者的腳步。
* **DeepSeek-R1 的開放衝擊**：2025 年初，一家中國實驗室把接近前緣水準的推理模型完全開放，引發「開放權重真的可能直逼封閉前緣」的震撼。支持者視為民主化的勝利，監管討論則把它當成「前緣能力外流」的案例。

這兩個例子說明同一件事：**同樣的釋出行為，會被兩個陣營讀出完全相反的意義。** 也正因為雙方都在真實案例上看到「自己擔心的那一面」，辯論才如此僵持。

## 監管可能長什麼樣：幾個具體的槓桿

如果真的立法，監管者手上大概有這幾種工具（以下是對「可能的做法」的客觀描述，不是建議）：

1. **算力門檻（release thresholds）**：以訓練算力畫一條線，超過才需要義務——歐盟《AI 法案》的「10²⁵ FLOPs」就是第一個實際例子。線以下：幾乎免責；線以上：要註冊、紅隊測試、通報事故。
2. **下游傷害的責任歸屬**：一個被微調過的開源模型造成傷害時，誰負責？目前各國都不清楚；討論中的方案從「開發者負責」到「平台／託管者負責」都有。
3. **來源登記與身分標記（provenance）**：要求公開服務的模型註冊（中國的備案制）、強制浮水印、建立「模型護照」。
4. **託管與雲端的義務**：對「分發權重的平台」課責——例如模型下載的實名制、限制特定類別。

每一種工具都有自己的代價：算力門檻可能被刻意做小的模型閃避；責任歸屬可能嚇退小型開發者；登記制度可能讓匿名研究與本地開發者邊緣化。**沒有一種工具是免費的**——這是為什麼辯論遲遲沒有結論。

> 整場辯論最該記住的一個詞：不可逆性（irreversibility）。權重一旦公開，就再也收不回來——所以所有監管討論，其實都在爭「公開之前那條線要畫在哪裡」。線之前，你管得到；線之後，只剩事後問責與風險分擔。

## 實驗室實際上在怎麼做：不等人立法

在立法之前，實驗室其實已經在自行「畫線」。幾種常見做法，都是事實描述而非評價：

* **分階段釋出（staged release）**：先給學術界與紅隊研究者評估，之後再全面公開。
* **可接受使用政策（acceptable use policy）**：權重可以下載，但授權合約禁止特定高風險用途（生物武器、詐騙、未授權監控等）。
* **門檻制授權**：某些釋出要求申請者說明用途、通過審核才給權重。
* **服務護欄**：把「開放權重」與「受控 API」並存——想要免費下載的人拿權重，想要安全護欄的人走 API。

這些做法的共通點是：**它們都在「公開之前」那條線上做文章**——因為所有人都知道，公開之後就沒有討價還價的空間了。把這條線畫出來，會更清楚：

```text
權重公開之前（還有得選）
→ 分階段、使用政策、門檻授權，都可以做
權重公開的那一刻（不可逆）
→ 複本開始擴散，權力交還給全世界
權重公開之後（只剩事後問責）
→ 責任歸屬、監控、補救，再也無法召回
```

## 現況一：歐盟怎麼對待開放權重

歐盟《AI 法案》是目前唯一把「開放權重」寫進法條的案例，它的處理方式是：

* **開放權重的 GPAI 模型，原則上豁免最重的義務**——只要不構成「系統性風險」（不超過算力門檻）。
* 這是立法過程中的刻意妥協：既要管住最頂級的前緣模型，又要保護開放生態不被誤傷。
* 但 GPAI 的「實務守則」（codes of practice）還在起草，開放社群正積極遊說，希望把「輕觸式」維持下去。

也就是說，**「開放權重該被怎麼管」在世界上最先進的法律裡，也還是一題未完成式。**

## 現況二：辯論現在站在哪裡

把鏡頭拉回來看辯論本身的狀態：

* **雙方都承認沒有定論**：開放開發到底「加速安全」還是「加速誤用」？雙方各執一詞，但沒人握有決定性的數據——這是個「尚未解開的實證問題」。
* **立場常被產業位置綁定**：做封閉 API 的公司主張控管，做開源生態的公司主張自由；學術界與小開發者通常站在開放這一邊。
* **算力鴻溝讓張力更尖銳**：`econ-03-compute-divide` 講過，訓練前緣模型的算力集中在極少數人手上；開放權重幾乎是「能力流到所有人手上」的唯一管道——這正是它同時被視為救星與威脅的原因。

## 這對開發者意味著什麼

如果你是開發者或研究者，現在這個時間點比較務實的態度：

1. **理解你手上的權重落在哪條線**：如果你用的是小模型（Llama、Mistral、Qwen 等級），目前絕大多數監管討論都不會壓到你頭上。
2. **留好合規彈性**：如果在歐盟市場部署，把「證明訓練資料來源、有著作權政策」當成基本功，這類要求正在變成常態。
3. **參與討論**：開放權重的未來，不是少數公司或政府能決定的，而是所有「跑過模型的人」集體態度的結果——包括你。

同時值得記住：這套「自我設限」不是法律，而是一種脆弱的默契。如果多數人繞過使用政策去部署，任何自願線都會形同虛設——這正是為什麼雙方都在努力，想把「默契」變成「有牙齒的規則」。

## 一句總結

開放權重是「可審計的透明」與「管不住的模型」這同一枚硬幣的兩面。開放陣營要的是審計與去中心化，封閉陣營要的是可控與可責；而監管討論的每一種工具，都是在畫「公開之前那條線」。到目前為止，連世界第一部 AI 法律都只給了一個「原則上豁免」的暫時答案。

到這裡，政策系列的三篇就完成了。如果你想回頭把「公開之前那條線」畫得更清楚，`policy-01-eu-ai-act` 有最完整的法律細節；要判斷各國下一步怎麼走，`policy-02-global` 是那張地圖。而規則最後總要落到具體的產品與決定上——書本的下一站，就是倫理與偏見。

* 開放權重模型一定比封閉模型更弱

* 權重一公開就無法收回，透明與擴散是同一件事的兩面

* 開放模型的訓練成本高到沒人負擔得起
