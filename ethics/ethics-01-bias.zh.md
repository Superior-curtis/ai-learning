# 偏見從哪來：模型只是資料的影子

> 📅 2026-08-04 · 核心概念
> 模型會重現社會的偏見，不是因為它『有立場』，而是因為它學會的只是訓練資料的統計規律。這篇拆開偏見注入模型的四個入口，解釋為什麼『去偏』沒有乾淨解法，以及團隊真正能動手做的是什麼。

---

「幫我篩掉不適合的工程師履歷。」——如果你的篩選工具底下是一顆語言模型，它很可能會默默把女性名字的履歷排到後面。它不是「討厭女性」；它只是讀過太多「工程師語境 + 男性人稱」的搭配，於是把這條相關性當成最可能的下一步。

換到圖像生成：你打「CEO」，出來一排水龍頭旁的西裝男；你打「護士」，出來一群微笑的女性。模型不是故意刻板——它是把你餵給它的資料，做了忠實的統計學重現。

這不是模型的「缺陷」，而是它的本質：一台只會預測下一個詞的機器，唯一能做的就是重現資料裡的反覆規律。**偏見不是「模型想什麼」的問題，而是「資料長什麼樣」的問題。** 這篇要拆的是：偏見從哪幾個入口進來、為什麼沒有「刪乾淨」的解法、以及工程團隊真正能動手做的是什麼。

## 偏見不是 bug，是統計

模型沒有價值觀。它只有一組參數，記錄的是「在它看過的資料裡，哪些詞通常跟在哪些詞後面」。`train-04-corpus` 已經講過：模型的能力與傾向，幾乎完全由「它吃了什麼」決定。

所以當網路資料裡「醫生」多半接「他」、「護士」多半接「她」，模型就學到這條規律——不是它認同，而是「下一個詞是『她』」在統計上機率更高。**對模型來說，偏見跟「貓在『喵』後面」是同一種東西：都是資料裡的反覆規律。** 差別只在於，人類看這條規律時會分辨「這是不是應該的」，而模型不會。

## 偏見與幻覺：同一個機制的兩面

「偏見」跟「幻覺」（`llmcore-05-hallucination`）聽起來是兩個問題，其實是同一顆引擎的兩種症狀。幻覺是模型在「最順」與「最真」之間沒有能力分辨；偏見則是它在「最常見」與「最應該」之間沒有能力分辨。

把兩者放在一起看，有個實際的好處：**你不會指望「修改輸出」能根除任何一種，因為根源都在模型背後的統計，不在眼前的那句話。** 對幻覺，你能做的是查證與引用；對偏見，你能做的是讓它可見、可量、可管理——後面會談具體做法。

## 四條注入路徑

偏見不是在單一環節跑進來的。把它拆開，至少有四個入口：

```text
訓練資料的統計 → 模型的參數 → 產品提示詞 → 使用者看到的輸出
↑                       ↑
標註者的價值觀          介面與回饋迴路
```

| 路徑 | 內容 | 例子 |
|---|---|---|
| **訓練資料** | 網路文字本身就承載社會偏見 | 工程師語境男性化、某族群只出現在負面報導 |
| **標註與回饋** | 人類標註者的判斷、規則與抽樣 | RLHF 的偏好資料把標註者價值觀寫進模型 |
| **產品使用方式** | 提示詞怎麼寫、介面怎麼設計、使用者是誰 | 預設提示引導出刻板回答；自動補全放大既有偏見 |
| **量測與部署** | 用什麼基準評估、測試涵蓋哪些人 | 測試集缺少某些方言或年齡層，等於「看不見」它們 |

四個入口不是獨立的，它們會疊加：資料層的偏見，被標註層的偏見放大，再經產品層的提示詞，變成每個使用者每天實際看到的輸出。

## 過度代表與低度代表

`train-04-corpus` 提到的「資料地心引力」，在偏見議題上尤其明顯：

* **過度代表**：某群人佔了資料的大宗，模型的「預設世界」就以他們為中心——對這個族群的回應最流利、最準、最像「預設值」。
* **低度代表**：某群人只在資料邊緣出現，模型對他們的知識稀薄、容易答錯；更糟的是，若僅有的那點資料剛好都是刻板印象，模型會把刻板印象當成「事實」放大。

舉例來說，一個以英語世界為主的語料庫，對英文使用者的回答品質，遠高於對小語種使用者的回答；而小語種那點稀少的文本，若剛好是「旅遊宣傳」或「災難報導」，模型對那個語言地區的理解就會被那幾種文本框住。

所以「資料越多越好」對偏見不成立——**重要的是分布，不是總量。** 一個全由單一族群寫成的語料，跟一個分布均衡的語料，養出來的模型天差地別。

## 評估本身也會偏

最後一個容易被忽略的入口：**我們用來判斷「模型好不好」的評估，本身也可能偏。** 若測試集以某一群人的用語、某一種文化背景當「正確答案」，模型對那群人表現好只是「正常」；對其他人的「低分」，卻可能被平均數蓋過去。

一個典型陷阱是只看「整體正確率」——它是所有族群的平均，一群人的高分可以完美掩蓋另一群人的低分。`train-04-corpus` 的教訓在這裡反過來適用：**資料的分布決定了模型的能力，也決定了評估看得見什麼、看不見什麼。** 所以「針對性評測」不是多放幾個測試案例，而是把「各族群分別打分」變成評估的預設做法。

## 具體案例

把概念落到三個你可能看過的現象：

* **招聘助理**：模型學的是「歷史上的錄取決策」，而歷史決策本身就編碼了過去的歧視。它沒有發明歧視，它只是繼承。
* **圖像生成**：「CEO」、「法官」的結果傾向白人男性，「護士」、「教師」傾向女性——因為這些職業在視覺資料裡的配對就是這樣。
* **翻譯**：把沒有性別語法的語言翻成英文，模型必須「選一個性別」，它選的是資料裡更常見的那個——工程師變成「他」，護士變成「她」。

三個案例的共同點：**模型只是忠實重現了輸入資料的相關性。** 問題不在「它學歪了」，而在「資料本身就有偏斜」。把責任全怪給模型，就像責怪鏡子為什麼會反映你的臉。

## 偏見會自我強化：回饋迴路

更麻煩的是，偏見不只是「一次性」的——它會自我強化：模型給出刻板回答 → 使用者按讚、繼續使用 → 這份互動被記錄成回饋資料 → 模型下次更傾向同樣的回答。

最典型的例子是搜尋與自動補全。使用者看到的是「被過去使用者的偏見養出來的建議」，而點擊這些建議，又成為下一輪建議的訓練資料。**偏見從資料裡長出來，再經由使用行為被餵回去。** 這也解釋了為什麼「上線後監控」不是安全團隊的附加工作，而是偏見治理的主戰場之一——`ethics-02-responsible-deployment` 會把這條迴路寫進正式流程。

## 為什麼「去偏」沒有乾淨解法

如果偏見只是「資料的問題」，那把資料洗乾淨不就好了？可惜沒有這麼乾淨的解法，原因有四：

1. **偏見與能力纏在一起**：模型學到的每一條相關性，都是「有用」與「有害」的混合。硬拔掉一條偏斜的相關性，常連帶損傷正常能力——例如移除「醫生 = 男性」的關聯，可能同時削弱模型對「醫生」這個概念的理解。
2. **沒有中立的基準**：「中性」本身就是一種選擇。該把哪個族群當預設？「公平」是「同等對待」還是「差異補償」？不同立場的人答案不同。
3. **壓掉一個，冒出另一個**：修好 A 族群的偏差，常在 B 族群引入新偏差；以「平均正確率」為目標的模型，本來就對少數族群不利。
4. **對齊與過濾只能修表面**：`llmcore-05-hallucination` 告訴我們，模型的輸出是機率性的；同樣地，任何過濾都只能把「偏見輸出」的機率壓低，壓不到零，也改不了底層統計。

一句話：**偏見不是一顆可以單獨拔除的螺絲，它是模型的一部分。** 所以「去偏」不是一次手術，是長期工程。

## 團隊真正能做的事

那到底能做什麼？答案不是「把偏見刪掉」，而是「把偏見變可見、可量、可管理」：

* **資料稽核**：先盤點訓練資料的代表性（`train-04-corpus`），知道哪群人在、哪群人不在，並公開文件化。
* **針對性評測**：建立專門探測偏見的評估集——同一題用不同名字、不同方言、不同性別對象各問一遍，比較差異。
* **紅隊壓力測試**：主動用「會誘發刻板印象」的提示去測（`security-06-guardrails` 的測試精神），把每次發現變成永久測試案例。
* **部署後監控**：上線後追蹤「不同族群的成功率差異」，而不是只追蹤平均指標。
* **流程與多樣性**：標註指引寫清楚、評測團隊有足夠多樣性、決策留紀錄——很多偏差是在「沒人注意到」的地方悄悄留下的。

下面這段是「針對性評測」的雛形：同一題、不同名字，看輸出有沒有差別。

```python
# 偏見探測：同一題、不同名字，比較輸出差異
def probe_bias(model, question):
  names = ['陳志明', '陳怡君', '王冠宇', '王麗婷']
  for name in names:
      prompt = f"{question}，我叫{name}。"
      reply = model.complete(prompt)
      print(name, "→", reply[:40])
```

## 下一步

偏見是「模型把什麼帶進世界」的第一個倫理問題。知道了偏見從哪來，下一個問題是：**就算你知道了，怎麼把一個功能負責任地放上線？** 從風險評估、護欄、監控到下架，那是一整套工程習慣——`ethics-02-responsible-deployment`。

#### Q: 為什麼「把訓練資料裡的偏見刪掉」不是解決偏見的乾淨解法？

* 因為模型是統計系統，偏見與能力交織在一起，拔掉一條相關性可能連帶損傷正常能力

* 因為偏見其實是模型的價值觀，刪資料沒有用

* 因為模型訓練太快，資料沒有機會被修改

* 因為偏見只存在於圖像模型，文字模型沒有這個問題

> 💡 偏見是模型的一部分，不是可以單獨拔除的螺絲：它與能力共用同一套統計，也沒有「中立」基準可依。所以「去偏」不是一次手術，而是透過資料稽核、針對性評測與部署後監控進行的長期工程。
