# 推理成本結構：一次「回答」的帳單

> 📅 2026-08-04 · 核心概念
> 按下發送，回答就出來了——但每一次生成都在燒 GPU 與電力。拆開 prefill 與 output 兩種 token，看懂一次呼叫真正貴在哪、重度使用者一個月又會燒掉多少。

---

按下發送鍵，模型幾乎是瞬間回你。於是我們很自然會想：「回答是免費的吧？」但恰恰相反——**每一次生成，都在燒一台很貴的機器**：GPU 在運轉、電力在消耗、晶片在折舊。最後這些都變成 API 帳單上「每百萬 token 多少錢」的數字，也就是 `industry-01-value-chain` 裡應用層生意的分母。

這一篇把一張帳單真正攤開：一次模型呼叫，錢花在哪、為什麼「輸出」比「輸入」貴、以及重度使用者一個月要付多少。理解了它，你就能讀懂為什麼有些 AI 產品收費、有些在燒錢。

## 一次呼叫的兩種 token

要算帳，先把一次呼叫拆成兩段。模型不是整坨「想完」再吐出來，而是像 `llmcore-01` 說的一樣——**先把你整段輸入讀進來，再一個字一個字把回答「擠」出來**。

| 面向 | Prefill（讀入） | Output（生成） |
|---|---|---|
| 在做什麼 | 一次看完你的整段提示詞 | 逐字寫出回答 |
| 計算方式 | 平行，一口氣算完 | 依序，一次只能算一個 |
| 速度量級 | 每秒數百到數千 token | 每秒幾十個 token |
| 計價 | 便宜 | 貴（通常好幾倍） |

「讀入」像一次把整頁講稿掃進腦子，「生成」像把答案一個字一個字說出來——後者慢得多，也貴得多。這不是定價者的偏好，而是硬體物理的直接結果。

## 為什麼輸出比較貴

貴的理由可以濃縮成一個概念：**不能平行**。生成每下一個 token，都依賴前一個 token，所以只能一個接一個來。更關鍵的是，每算一個 token，模型都要把全部權重從記憶體讀一遍（也就是整顆「腦」過一遍），這在硬體上是被「記憶體頻寬」卡住的，跟你主觀想不想加速無關。

三個直接後果：

* **時間等於金錢**：GPU 是按小時計費的資產。生成 1000 個 token 要十幾秒，GPU 就實打實跑十幾秒。
* **批次攤不平**：讀入那一段可以好幾個請求並排一起算、把成本攤薄；生成因為是依序的，攤薄空間小得多。
* **佔住整台機器**：生成期間整顆 GPU 都被這個請求佔住，沒辦法中途去服務別人。

所以幾乎所有 API 牌價都是「讀入便宜、輸出貴」，而且貴的不是一點點。搞清楚誰在付哪種錢，是讀懂所有 AI 產品定價的第一步——很多被質疑「怎麼收這麼貴」的服務，成本其實就藏在輸出這一側。

## 硬體攤提：GPU 的租金藏在哪裡

就算不看 GPU 本身，錢也藏在別處——**攤提（amortization）**。一台旗艦 GPU 動輒數萬美元，不是用一年就丟，而是要算進它能服務的每一秒裡：除以它 3~5 年的壽命、再除以它真正被用到的比例，最後攤到每一百萬個 token 上。

這帶出推理成本最容易被忽略的一句話：**GPU 空轉照樣燒錢**。電要付、折舊要攤、機房要養。供應商真正的成本是「GPU 小時 × 利用率」，而不是「輸出了幾個字」。理解了這句，你就明白為什麼供應商拼命推快取、拼命提高吞吐——那都是在提高同一個分母的利用率，也是在把固定成本攤到更多 token 上。

## 一組單位經濟學：攤給你看

把上面的概念算成數字。以下是一組「示意」假設，不是真實牌價，但骨架跟你在帳單上看到的一模一樣：

```python
# 單位經濟示意：不是真實牌價，但結構一樣
input_tokens  = 2000    # 提示詞長度
output_tokens = 1000    # 要生成的回答長度

price_in  = 2.50  / 1_000_000   # prefill：每 token 的成本
price_out = 15.00 / 1_000_000   # output：每 token 的成本（貴很多）

call_cost = input_tokens * price_in + output_tokens * price_out
print("單次呼叫成本：$%.4f" % call_cost)

# 時間：讀入可以平行，生成只能逐字
prefill_s = input_tokens / 500    # 假設每秒 500 token 讀入
output_s  = output_tokens / 60    # 假設每秒 60 token 生成
print("讀入約 %.1f 秒，生成約 %.1f 秒" % (prefill_s, output_s))

# 重度使用者：每天 50 次呼叫
monthly = call_cost * 50 * 30
print("重度使用者每月成本：$%.1f" % monthly)
```

跑一次（試著心算也行）：單次呼叫約 0.005 + 0.015 = **0.02 美元**；一個每天叫 50 次的用戶，一個月就是 **30 美元**左右的純推理成本。輸出佔了大半——1000 個輸出 token 的帳單，比 2000 個輸入 token 還貴三倍。

> 記住這一句：prefill 便宜、output 貴。 看懂錢往哪個方向流，就知道該往哪裡省——大部分省錢招式，本質上都在「減少輸出 token」或「讓模型少生成一點」。

## 從一次呼叫到每月帳單

一次呼叫 0.02 美元聽起來不多，但把它放大就很有感：

| 情境 | 每次呼叫成本 | 用量 | 每月純推理成本 |
|---|---|---|---|
| 輕度使用者 | $0.002 | 每天 5 次 | 約 $0.3 |
| 一般使用者 | $0.02 | 每天 50 次 | 約 $30 |
| 重度 / 代理 | $0.05 | 每天 200 次 | 約 $300 |

這張表解釋了 `industry-01-value-chain` 裡應用層為什麼「毛利分化」：同樣一個功能，用戶把它當偶爾查一下的工具、還是當整天黏著的助手，你的成本會差一百倍。**輸出行業（聊天、代理）比讀入行業（摘要、檢索）燒錢快得多**，這也決定了這兩種產品的定價與獲客策略必須完全不同。

#### 對照 / Comparison

## 用單位經濟反推你的訂價

0.02 美元是「成本」，不是「營收」。要把它變成生意，你得反推出訂價：假設目標毛利率 60%、每次成本 0.02 美元，這通電話至少要收約 0.05 美元才不虧——而且還不含獲客與營運。數字本身是示意，重點是這條思路：

| 每次成本 | 目標毛利 | 需收訂價 | 月 ARPU（50 次/月） |
|---|---|---|---|
| $0.02 | 40% | ~$0.033 | ~$1.7 |
| $0.02 | 60% | ~$0.05 | ~$2.5 |
| $0.02 | 80% | ~$0.10 | ~$5 |

太多 AI 產品把成本放到最後才算，結果就是「用戶越多、虧越多」。**健康的單位經濟是反推出來的：先算成本，再定價，而不是先定價、再祈禱成本夠低。**

## 這張帳單怎麼用

看懂結構，省錢的三個槓桿就浮出來了：

1. **少生成**：提示詞裡要求「簡短回答」，比任何折扣都有效——省的是最貴的 output。
2. **快取重複的輸入**：同一份提示詞重複送，讀入那段的帳可以省掉；各家快取的規則不同，真正的計價細節看 `providers-02-pricing`。
3. **分層用模型**：簡單任務交給便宜的小模型，難題才上旗艦（見 `models-05-small-models`）。

更重要的是心態上的轉變：**推理成本不是「運氣」，而是可設計的變數。** 把 token 當作真正的資源去優化，你的產品經濟會比其他團隊健康很多。

## 什麼時候「成本」真的會壓死人

成本重不重，看兩個數：**單次成本 × 呼叫次數**。幾個典型場景，成本一不注意就變成生死線：

* **高頻低價**：自動補全、批量翻譯、逐字稿——單次成本不高，但你一天可能低價賣出幾百萬次。差一個數量級，就吃掉整季毛利。
* **代理迴圈**：一個「任務」不只是一次呼叫。`agents-02-orchestration` 談過，代理常拆成十幾、幾十步，每步一次呼叫——這把單次成本放大了十倍以上。
* **輸出特大**：長報告、長回覆——output 越長，越燒錢。

反過來，有些場景成本根本不重要：你賣的是「結果的品質」而不是「token 的量」，且客單價夠高。**判斷標準很簡單：當推理成本接近或超過每個用戶帶來的營收，它就是生死線；否則，把精力花在產品價值上更划算。**

## 效率飛輪：為什麼長期成本會往下掉

token 的單價不是恆定的——產業裡有股力量在把它往下推：

* **更好的晶片**：新一代硬體讓每 token 的運算成本逐年下降（詳見 `econ-02-gpu-economics`）。
* **更小的模型**：蒸餾與量化讓「夠好的能力」能用更小的模型跑，`models-05-small-models` 與 `llm-04-quantization` 都是這條線上的工具。
* **工程優化**：快取、批次、推論伺服器——供應商與開源社群其實在做同一件事：提高每顆 GPU 的產出。

但要注意另一邊：**每次成本下跌，都會被「用得更兇」接住。** 用戶會要求更長的輸出、代理會拆出更多步驟、產品會把 AI 塞進更多角落。所以與其追「今天的價格」，不如盯「成本結構」——懂結構的人，能在每一次效率躍進時重新設計自己的產品，而不是被帳單追著跑。

## 下一步

看完一次呼叫的帳單，下一個問題自然浮現：**為什麼 GPU 這麼貴、而且是全產業的瓶頸？** 這就是 `econ-02-gpu-economics` 要回答的。

#### Q: 同樣是 1 個 token，為什麼「生成」（output）通常比「讀入」（prefill）貴？

* 因為生成的文字品質比較好

* 因為生成只能依序逐個進行，GPU 必須全程亮著等它，且每步都要把整個模型讀一遍

* 因為讀入的 token 通常比較短

* 因為供應商想多賺錢沒有別的原因

> 💡 生成依賴前一個 token，無法平行；每個 token 都要把全部權重讀一遍（記憶體頻寬瓶頸），時間等於成本，所以計價更高。
