# 資料準備與評估：微調的勝負手

> 📅 2026-08-04 · 深入研究
> LoRA 讓微調便宜，但真正的勝負手是資料與評估。怎麼備資料、怎麼拆驗證、怎麼證明「真的變好」、怎麼避開過擬合與遺忘。

---

`finetune-02-lora` 教你把微調變便宜。便宜是條件，不是結果——工具再順，拿髒資料去跑，出來還是髒模型。這篇講真正的勝負手：**資料準備**與**評估**。備得乾淨、量得對，你才知道微調到底有沒有變好，而不是自我感覺良好。

## 好資料長什麼樣

先回到 `train-02-finetuning` 的精神：微調是「用你的資料把模型從通用推向特化」。所以資料的本質是**示範**——你希望模型之後怎麼回覆，資料就該長什麼樣。三個關鍵：

**1. 品質優先於數量。** 一條寫得漂亮、符合你目標格式的範例，勝過十條含糊的。每條資料都要是你「願意照抄」的回覆。

**2. 去重。** 重複資料會讓模型對那幾條過度「背誦」，擠壓它對其他模式的學習。跑個簡單的近似去重（n-gram 或 embedding 相似度），把近乎相同的範例清掉。

**3. 格式一致。** 這是新手最容易忽略的：模型的輸入與輸出格式要跟你「上線時真正會用」的一致。如果你上線時會給系統提示詞，訓練資料也要長那樣；如果希望回覆是 JSON，每條示範都要是合法的 JSON。

### 一張「好示範」v.s. 一張「壞示範」

同一件事，差別一眼可見。假設你要教客服模型用條列點回覆：

| 壞示範 | 好示範 |
|---|---|
| 輸入：「退貨政策？」<br />輸出：「很抱歉，您可以退貨。具體政策請看官網。」 | 輸入：「退貨政策？」<br />輸出：「很抱歉造成困擾！關於退貨：<br />• 收貨後 7 天內可申請<br />• 需保留原包裝<br />• 退款 3–5 個工作天到帳<br />還有其他想確認的嗎？」 |

壞示範語氣鬆散、沒有結構、還想「請看官網」——這會教模型偷懶。好示範把「先道歉、條列點、結尾詢問」一次教齊。**每條資料都是教材，壞教材會被學進去。**

> 實務鐵律：微調資料是「示範」，不是「事實資料庫」。 每條資料都在教模型「遇到這種輸入，該怎麼回」——所以輸入要貼近真實、輸出要值得照抄、格式要跟正式環境一致。

## 拆訓練／驗證集：先別自我感覺良好

微調最容易犯的錯是「訓練完很開心，上線才發現只背下訓練集」。對策很老派：**留一份驗證集，從頭到尾不讓它見到訓練。**

* **訓練集**：用來跑微調的那 90% 左右。
* **驗證集**：完全沒參與訓練的那 10% 左右，訓練時「偷偷」留著，最後拿它量泛化。

如果訓練集準確率一直升、驗證集卻卡住或往下掉，就是典型的過擬合訊號——模型開始「背」而不是「學」。

#### 動手前先切

把資料切成訓練 90% / 驗證 10%，驗證那 10% 之後絕不進訓練。

#### 訓練時偷看曲線

訓練準確率一直升、驗證停滯或下滑 → 過擬合訊號，準備早停。

#### 最後只評驗證

模型選定後，用從未見過的驗證集做最終評分。

## 怎麼量「真的變好了」

評估微調的效果，分兩條線：**行為測試**與**回歸測試**。

**行為測試：目標行為有沒有出現。** 準備一份**金準提示集（golden set）**——二十到五十條真實會出現的提示，人工標好「理想回覆」。微調前後各跑一遍，對照：

* 格式對不對？（開頭、結尾、欄位、語氣）
* 內容對不對？（事實、關鍵字、結構）
* 跟人工標的理想回覆差多少？

**回歸測試：原本能力有沒有退化。** 微調是「特化」，往往伴隨「遺忘」——模型可能開始把領域外問題也硬拗成你的格式。所以留一份「一般能力」測試集（例如摘要、翻譯、常識問答各幾條），確認微調後沒把原本的本事弄壞。

### 怎麼算「過關」

行為測試的分數不需要完美，但要**可重複、可對照**：

| 檢查項 | 過關的長相 |
|---|---|
| 格式合規 | 每一條回覆都符合目標結構（例如都是 JSON、都條列） |
| 內容命中 | 關鍵字／事實命中率達你設定的門檻 |
| 語氣一致 | 抽樣人工看，不像「預設模型」的回覆 |
| 回歸未退 | 一般能力測試集的分數沒有明顯下滑 |

門檻不假外求——**動手前先量「未微調」的基線**，之後每輪都跟基線對照。進步有沒有、退化有沒有，全部以基線為準，才不會自我感覺良好。

```評估示意
# 拆分：訓練 vs 驗證（驗證絕不進訓練）
train, val = split(dataset, ratio=0.9)

# 行為測試：固定的金準提示集
for prompt, ideal in golden_set:
  out = model.generate(prompt)
  score += check_format(out, ideal)   # 格式 + 內容

# 回歸測試：確認沒忘掉原本能力
assert general_ability(model, baseline) >= threshold
```

## 過擬合與災難性遺忘：兩個要盯的敵人

* **過擬合**：只背下訓練資料，驗證集表現變差。防法：少而乾淨的資料、合理 rank（見 `finetune-02-lora`）、留驗證集、適時早停。
* **遺忘（catastrophic forgetting）**：學新東西時把舊能力沖掉。防法：訓練資料裡混進一小撮「通用能力」範例，回歸測試盯住它。

一句話：**「學得進、記得牢、不丟舊」三個目標互相拉扯**，評估就是給這三件事同時打分。

> 兩個敵人用同一套武器防：留一套「從未進過訓練」的資料，讓它同時當驗證與回歸的標尺。 過擬合看驗證有沒有掉，遺忘看回歸有沒有掉，缺一不可。

## 一套最小評估流程

不用搞到學術等級，實務上一套就夠：

1. **動手前先量基線**：用「未微調」的 base model 跑一遍金準集，記下分數。
2. **微調後再量一遍**：同一套金準集，同一份回歸集。
3. **對照三件事**：目標行為有沒進步？一般能力有沒有退化？退化能不能接受？
4. 不滿意就回頭改資料或 rank，再來一輪——評估不是一次性的期末考，是每一輪微調的儀表板。

還有一件事常被漏掉：**把「評估資料」跟「訓練資料」分得夠乾淨。** 金準集如果混進訓練集，分數好看全是假象。這跟你拆驗證集是同一件事，只是記得連「評估提示」本身都不要從訓練資料裡抄。

這套流程跟「評模型多強」的整體框架相通，之後 `models-06-evaluation` 會把它放大到基準（benchmark）層級。現在先讓它在單一微調任務上運作。

## 收尾：資料與評估，才是微調真正的分水嶺

LoRA 把門檻降低，真正決定「這顆微調模型能不能上線」的，是資料乾不乾淨、評估誠不誠實。把這套「先切驗證、先量基線、每輪對照」的習慣養起來，你就不會被訓練曲線騙，也不會把只會背資料的模型送進生產。

#### Q: 微調完，訓練集準確率很高，但留出的驗證集表現卻開始下滑。最可能是什麼？

* 驗證集資料太少，不準

* 模型開始過擬合——只背訓練資料，沒在學泛化

* rank 太低，學不夠

* 資料格式不一致

> 💡 訓練集一直升、驗證集停滯或下滑，是典型的過擬合訊號：模型開始背誦而非泛化。對策是資料少而乾淨、合理 rank、留驗證集並適時早停。
