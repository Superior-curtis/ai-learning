# LoRA 實務：把微調變便宜

> 📅 2026-08-04 · 深入研究
> 從 LoRA 的概念走到能動手。拆解 adapter 是什麼、rank 怎麼取、要多少資料、用什麼工具、最後怎麼融合與量化。

---

`train-02-finetuning` 留了一個口頭禪：LoRA 是「微調便宜的秘密」。概念上好懂——不碰所有權重，只在一條小旁路上加點低秩參數。但「知道概念」和「能把一個 adapter 磨出來」之間還差一截。這篇把它講到你能動手：adapter 到底是什麼、rank 怎麼取、要多少資料、用什麼工具、最後怎麼變小帶走。

## 一句話複習：LoRA 的賭注

完整微調要更新全部權重（一個 7B 模型就是七十億個參數）。LoRA 賭的是：**你需要的變動，其實只住在一個很小的「低秩」空間裡。**

做法是：在原模型某些層的旁邊，插入兩片小小的矩陣（A 和 B），相乘之後效果就相當於「對那層做小調整」。你只訓練這兩片，其餘全部凍結。訓練完，這兩片矩陣合起來就是一個 **adapter**。

```text
完整微調：更新 70 億個參數
LoRA：     只更新 幾百萬 個 adapter 參數（常常不到 1%）
```

視覺上它長這樣——原權重完全沒動，動的只是掛在旁邊的小旁路：

```text
凍結的原權重 W（不動）
│
└── 旁路：A（小）→ B（小）→ 輸出 = A×B 的微調量
│
訓練時只更新 A、B，W 保持不變
```

## Adapter 到底是什麼

**Adapter 就是那兩片訓練好的小矩陣**——程式上常常就是一個 `.safetensors` 檔，幾 MB 到幾十 MB。它不自己完成任務，它沒跟原模型合體之前什麼都不是；它必須「疊」在原模型上，給每一層一個微小的偏移，才讓整體行為變成你要的那樣。

這也解釋了兩件實務上的事：

* 同一個 base model 可以疊好幾個不同 adapter，各管一件事（一個管語氣、一個管摘要），要哪個就掛哪個。
* Base model 不用複製——你 GPU 上只需要一份，換 adapter 只換那幾 MB。

## Rank：一個小小的數字，決定品質與大小

LoRA 的核心參數叫 **rank（秩，通常寫作 `r`）**。它決定旁路「多寬」，也決定 adapter 多大、效果多貼近全參數微調。

| rank | 意涵 | 代價 |
|---|---|---|
| 低（r = 4~8） | 旁路窄，adapter 小、速度省 | 表達力較低，複雜任務可能學不足 |
| 中（r = 16~32） | 一般任務的甜蜜點 | 折衷 |
| 高（r = 64+） | 更接近完整微調 | adapter 變大，收益遞減 |

通則：**先從 r = 16 起步**，看不夠再往上。不是 rank 越高越好——等你升到差不多夠用，再加通常只是讓 adapter 變胖、過擬合風險上升，效果卻不見得變好。

> 實務鐵律：LoRA 讓你「用幾百萬個參數」去逼近「全參數微調」的效果，而不是取代它。 rank 是「效果 vs 大小」的旋鈕，先從 r ≈ 16 試，別一上來就拉滿。

### 兩個更小的旋鈕：alpha 與 target_modules

rank 之外，有兩個參數常讓新手困惑，其實意思都不複雜：

* **`lora_alpha`**：旁路輸出要乘多少倍再疊回原權重。直覺上它控制「這條旁路的音量」。起點常取 rank 的兩倍（r=16 → alpha=32），後續微調只是「相對強度」的選擇，不是越大越好。
* **`target_modules`**：旁路要掛在哪幾種層上。掛愈多層 → 學習力愈強、adapter 愈大、也愈貴。省錢起點常是只掛 Q、V 兩類投影（如 `["q_proj", "v_proj"]`），不夠再加。

一句話：rank 決定「寬」，alpha 決定「音量」，target 決定「掛多廣」。三個都小，LoRA 就真的又小又快。

## 要多少資料？

很多人對微調的資料量有幻想，LoRA 反而把需求降得更低。粗略量級：

* **風格／語氣**：幾百條高品質範例就夠。你要的是「相對小、相對固定」的轉變。
* **固定技能／結構化輸出**：幾百到幾千條。越多不代表越好，前提是「品質與一致性」。
* 對比：全參數或大規模微調要的是幾千到上萬，LoRA 常常只要它的零頭。

真正的瓶頸幾乎總在**資料品質**，不在數量——這正是下一篇 `finetune-03-data-and-eval` 要拆解的。現在先記住：**少而乾淨，勝過多而髒。**

## 用什麼工具

讓 LoRA 從「概念」掉到「一行切換」的主要是兩個工具：

* **HF PEFT**：現在事實上的標準，`get_peft_model` 一行把 LoRA 套上去，生態最完整。
* **Unsloth**：主打快與省記憶體，號稱最高能把訓練與記憶體需求砍掉很大一塊，對消費級 GPU 特別友善。

下面是套上 LoRA 的示意，精神就是「包一層、只訓旁路」。

```peft&#x20;lora
from peft import LoraConfig, get_peft_model

lora = LoraConfig(
  r=16,           # 秩：越大越貼近全參數、adapter 越大
  lora_alpha=32,  # 縮放，通常取 rank 的兩倍當起點
  target_modules=["q_proj", "v_proj"],  # 只挑某些層
)
model = get_peft_model(base_model, lora)
# 只有 adapter 參數會被訓練，其餘全部凍結
```

如果只想快、不想碰細節，Unsloth 通常只要換幾行 import，框架幫你處理位元數與最佳化。

## 融合與量化：最後的變小術

訓練完你有兩個選擇：

**1. 融合（merge/fuse）。** 有人不想要「base + adapter」兩件套，想把效果直接焊死回原權重，變成一個普通模型檔。`PeftModel.merge_and_unload()` 就是幹這個——產出一個完整權重的模型。代價是它跟你選的 base model 一樣大（GB 級）。

**2. 量化（quantization）。** 想把 base model 本身縮小、省記憶體，就到 `llm-04-quantization` 那套：用更少位元表示權重。LoRA 與量化可以疊著用——基礎量化 + LoRA 訓練，常是「一張消費級 GPU 也想微調」的進階做法。

> 記住這組關係：adapter 是「改動」，base 是「底子」。 融合是把改動焊回底子（變成一顆大檔），不融合就是「小改動＋大底子」兩件套隨身攜帶。兩者各有適用場合，沒有誰比較「正確」。

## 輸出到底有多小

關鍵數字：**adapter 通常落在「幾 MB 到幾十 MB」**。對比 base model 動輒著 GB 計算：

| 產物 | 大小量級 |
|---|---|
| base model（7B，FP16） | 約 14 GB |
| LoRA adapter | 約 5~80 MB |
| 量化後的 base model | 視位元數，約 4~8 GB |

所以 finetune 的「可攜帶專長」就是那只 adapter——它可以塞進 git repo、放雲端、換台機器掛上就變身。真正想拖走的「完整模型」仍是 base + adapter 的組合，或融合後那個 GB 級檔。

## 新手最容易踩的三個雷

**1. rank 拉太高。** 覺得「rank 越大越強」，直接把 r 拉到 128。結果 adapter 變大、顯卡變慢、效果沒有更好，還更容易過擬合。先從 16 開始。

**2. 資料髒而不自知。** 用重複、格式混亂的資料去訓，模型把髒格式也「學」進去，上線才發現回覆東歪西扭。資料品質是 LoRA 的上限，下一篇會拆。

**3. 拿 LoRA 解「知識更新」。** 每週變的產品資料不是 LoRA 的題——那是 RAG 的題（見 `finetune-01-finetune-vs-rag`）。LoRA 學固定模式，學不會「隨時要變」的東西。

## 小結

LoRA 讓你用一點資料、一點顯卡、一只小檔，學會固定技能，還不碰那顆幾十 GB 的心臟。到這裡你已經知道「怎麼變便宜」；下一篇接著問更關鍵的：**訓練資料怎麼備、改完怎麼評估它真的變好**（`finetune-03-data-and-eval`）。

#### Q: 你訓練完一個 LoRA adapter，發現效果不錯但 adapter 偏大。想縮小它，優先該動哪個參數？

* 調低 rank（例如 16 → 8）

* 換一個更大的 base model

* 增加訓練步數

* 把 lora_alpha 調到超大

> 💡 rank 直接決定旁路寬度與 adapter 大小。調低 rank 讓旁路變窄、adapter 變小，代價是表達力略降。改大 base model 或猛加步數只會更貴更重，alpha 也不是「越大越好」。
