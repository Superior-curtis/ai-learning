## 從原始碼看 Claude Code 的產品邊界與局限

Claude Code 很強，但研究一個系統如果只看它「做到了什麼」，很容易失真。更有價值的做法，是同時看它：為什麼強、為什麼要這麼複雜、以及它的邊界和代價是什麼。

***

### 五條關鍵邊界

1
高度依賴工具與上下文強不是憑模型裸奔得來的。工具、上下文、權限、狀態等配套能力缺位，表現會明顯下降。2
系統複雜度極高main.tsx 極重、commands.ts 極長、AppState 很複雜——代價是維護成本高、心智負擔重。3
安全不是可選項，而是持續負擔越強的工具越需要強權限治理。長期成本就是必須不斷維護安全邊界。4
不是所有問題都值得交給它強在「工程閉環」，不適合極簡單的一次性問答或無明確邊界的開放式探索。5
產品能力和組織能力綁定很深Remote Session、MCP、LSP、Plugins、Skills、Plan Mode、Multi-Agent—更像長期演化的平台。

***

### 邊界 1：強能力來自配套，不只來自模型

🧠
模型🔧
工具📋
上下文🛂
權限💾
狀態管理它不是「換個模型就能複製」——配套能力缺位，表現會明顯下降。

***

### 邊界 3：安全循環

🔋 更多執行能力→📈 更高自動化價值→⚠️ 更高安全風險→🛡️ 更多權限限制

***

### 邊界 4：適合 vs 不適合

✅ 適合🔧 工程任務拆解
📂 跨檔案理解和修改
🔄 專案上下文中持續推進❌ 不適合💬 極簡單的一次性問答
🏜️ 無可執行環境的純討論
🌌 缺乏明確邊界的開放探索

***

### 為什麼很難被快速複刻

很多人看到 Claude Code，會覺得「無非就是模型 + tools」。但從原始碼看，真正難的不是把工具接進去，而是把下面這些**同時做穩**：

✓工具協定統一✓上下文治理✓權限系統✓狀態系統✓遠端和任務能力✓UI 與審批流程

***

### 一句話總結

> Claude Code 強在**工程閉環與平台化能力**，但代價是系統複雜度、安全治理負擔和執行時期裝配成本都非常高——這也是理解它時必須同時看到的另一面。
