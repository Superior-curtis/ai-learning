## 遠端會話與橋接能力：終端在本地，不代表執行一定在本地

從很多人的直覺看，Claude Code 是一個本地終端工具。但原始碼很清楚地表明，它已經內建了不少遠端能力：**remote session、direct connect、bridge/remote-control、SSH 相關流程**。它的 UI、執行位置和會話位置可以**分離**。

***

### 入口層的證據

`main.tsx` 裡直接有這些導入：

遠端能力不是後面某個插件臨時加的，而是**入口層就正式考慮的運行型態**。

***

### AppState 的遠端狀態

看到這組欄位，基本可以確定兩件事：

1. 遠端能力已經不是一次性請求，而是**長期連線狀態**
2. 系統要處理連線、活躍、重連、橋接、環境 ID 等完整生命週期

***

### Remote Session vs Bridge

🌍 Remote Session會話運行在遠端
遠端擁有執行權🔗 Bridge / Remote Control本地 REPL 暴露遠端接入通道
本地 UI 控制遠端 Agent

兩者都屬於「**本地 UI 和執行位置分離**」的範疇，但語義不完全相同。
