## Slash Commands 命令系統：使用者如何直接控制 Claude Code

Claude Code 裡有兩套很容易混淆的機制：

🔧
工具系統
給模型調用
FileRead, Bash, WebSearch...⌘
命令系統
給使用者顯式輸入
/config, /mcp, /review, /plugin...

比如 `/config`、`/mcp`、`/review`、`/plugin` 這類東西，不是讓模型在主循環裡隨便呼叫的，而是使用者主動觸發的**控制入口**。

***

### 使用者輸入的分流

使用者輸入以 / 開頭？YES → 命令處理器配置 / 狀態 / 子功能界面
直接控制系統行為NO → QueryEngine模型 + 工具循環
AI 自動判斷處理方式

### 互動練習：命令 vs 自然語言

配對：適合用命令還是自然語言？切換模型
→
/model 命令重構檔案的函數
→
自然語言任務查看用量統計
→
/usage 命令解釋錯誤訊息
→
自然語言任務審查程式碼變更
→
/review 命令管理 MCP 伺服器
→
/mcp 命令規則： 當目標是「讓系統進入明確狀態」時用命令；當目標是「讓模型推理和執行任務」時用自然語言。

***

### 使用者為什麼需要命令系統？

如果一切都交給模型自動決定，系統會很強，但也會失去明確控制。

🎯
顯式觸發
有些操作適合人主動發起⚡
確定性流程
管理動作需要確定性流程🛂
控制面任務
配置權限不該 AI 模糊處理

### 背後的工程思考

命令系統不只是執行器，還是整個產品功能地圖的一部分。

1.命令層是能力組織方式
commands.ts 把龐雜能力按主題歸類：配置類、狀態類、MCP/插件類等。2.與工具系統共享底層世界
受同樣的配置和 feature gate 影響，同樣讀寫 AppState — 只是使用者不同。3.成熟產品保留命令面
好的工具不只會自動幹活，還要讓你能明確接管、切換和管理執行環境。

***

### 一句話總結

> **命令**是「人直接作業系統」的入口，**工具**是「模型代替人作業系統」的入口。兩者共享同一套底層世界，只是使用者不同。
