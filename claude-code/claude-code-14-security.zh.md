## 權限與安全機制：為什麼 Claude Code 不會無腦亂跑

一旦一個 AI 系統能讀寫檔案、執行命令、存取外部資源，安全問題就不再是附屬功能，而是**主功能的一部分**。

Claude Code 在這件事上明顯下了很大功夫——它不是事後補丁式安全，而是**架構級安全**。

***

### 權限決策流程圖

🧠 模型想呼叫工具⬇工具對目前 session 可見？⬇匹配 allow / deny / ask 規則✅ allow
放行執行❓ ask
彈出權限請求🚫 deny
記錄拒絕並回流

***

### 權限不是單點判斷，而是多層控制

從原始碼結構看，Claude Code 的權限體系至少有六層：

🛂

***

### 有些工具甚至不會先暴露給模型

這是很關鍵的一點。`tools.ts` 中的過濾邏輯說明，某些工具會在模型看到它們之前就先被剔除。

📦 全部工具⬇可見性過濾
（環境 / feature gate / deny rules）⬇🎯 模型能看到的工具⬇ 發起呼叫執行時期權限判斷
（執行 / 詢問 / 拒絕）

安全策略不只是執行時期攔截，還包括：**能力暴露控制**、**工具可見性控制**、**環境級可用性控制**。這比單純在工具執行時做確認更穩。

***

### 為什麼這套機制對多 Agent 場景更重要？

一旦系統支援子 Agent、後台任務、遠端連線，權限問題會立刻變複雜：

誰可以彈權限框？誰只能自動拒絕？哪些動作能在後台執行？哪些規則必須前置生效？

***

### 設計目標不是完全自動，而是「可控自動」

> Claude Code 的目標並不是把使用者完全踢出流程。更準確地說，它追求的是：能自動推進任務，但關鍵動作要可約束，在不同模式和上下文下權限策略能靈活調整。

***

### 一句話總結

> Claude Code 不會無腦亂跑，不是因為模型天然謹慎，而是因為系統在**工具暴露、呼叫審批、模式控制和規則匹配**上都做了大量設計——這也是為什麼它能把 Agent 執行動作真正帶進工程工作流裡。
