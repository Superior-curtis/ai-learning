## Tool 工具系統：Claude Code 的執行力來自工具，不只來自模型

很多人討論 AI 程式設計時，容易把注意力全部放在模型上。但從 Claude Code 原始碼來看，真正讓它「能幹活」的，是模型外面的**工具系統**。

***

沒有工具，Claude Code 再強也只是會分析程式碼。有了工具，它才能真正讀檔案、改檔案、跑命令、接 MCP、問使用者、開子任務。

模型
分析程式碼 → 輸出建議⬇工具系統
讀檔、改檔、跑命令、搜尋、MCP...⬇執行
實際改寫檔案、部署、查資料...

***

### Tool.ts 負責定義統一協議

**Tool.ts** 不是某個具體工具實作，而是全系統的工具抽象層。最重要的價值有二：

① 統一語義統一定義工具的輸入、輸出、上下文和權限語義② 統一契約給所有工具提供相同的執行契約

***

### tools.ts：系統的工具目錄

如果 **Tool.ts** 定義的是協定，那 **tools.ts** 定義的就是「這次系統到底有哪些工具」。

**兩點值得注意：**

1. Claude Code 的能力面非常寬——不止讀寫檔案和 Bash
2. 工具集不是死的——會受環境變數和 feature 條件影響

### 工具不是全量暴露，而是動態篩選

關鍵在於 `filterToolsByDenyRules`——工具會在模型看到它們之前就先被權限規則過濾。

### 為什麼統一工具協議特別重要？

一旦協議穩定，新增能力的方式變得非常可預測：

1
新能力實作自己的 Tool2

註冊到工具目錄4
在合適條件下暴露給模型

### 一句話總結

> 用統一的 **Tool** 協議，把檔案系統、終端、搜尋、外部整合和智能體能力包裝成模型可呼叫、可控、可擴展的執行層。

理解了這層，你就能明白它為什麼不是「聊天 + 插件」的簡單組合，而是一個真正可操作的工程代理。
