### 為什麼要這樣拆

前三個模組是「能不能跑起來」；第四、五個是「能不能在真實工程環境跑得穩」；第六、七個是「能不能把任務真正做閉」；第八個是「能不能從單機走向平台」。多數 demo 產品垮在第六與第七之間——能展示、不能交付。

先決條件有運行時，才有工具；有上下文與權限，才有自動化上限實作順序主循環 → 檔案/Shell → 上下文+權限 → 狀態系統 → 最後才碰 MCP/遠端/多 Agent核心心智不是某個神奇 prompt，而是模組化思維本身

***

### 一句話總結

> 做 Claude Code 最值得學的不是任何一段程式碼，而是這個**分層順序**：先有運行時再有工具，先有上下文與權限再談自動化上限，先把單執行緒跑穩再擴到平台化能力。
