## 多 Agent 與子任務機制：從單執行緒到協作系統

如果只把 Claude Code 看成「一個主對話框裡的模型」，你會錯過它很重要的一條演化方向：它已經明顯在支援**多 Agent、子任務和協作型運行**。

***

### 工具層的入口

多 Agent 能力不是隱藏實驗，而是被當成**正式工具體系的一部分**。

***

### 整體結構

🧑‍💼 主執行緒 AgentAgentTool
派生子 Agent
獨立上下文字窗Task* Tools
建立/管理任務
獨立工具執行SendMessage
Agent 間通訊
結果回傳

***

### 狀態層的支援

AppState 裡已經為多 Agent 預留了位置：

tasks
統一任務表agentNameRegistry
Agent 名稱路由viewingAgentTaskId
查看特定 Agent 記錄

UI 層和執行時期層都已經接受了「不是只有一個主執行緒」的事實。

***

### 為什麼要做多 Agent？

複雜工程任務天然可拆分：

🔍 Agent A 查程式碼結構
🧪 Agent B 跑測試
📦 Agent C 處理子模組⬇ 各自獨立執行主執行緒匯總 → 繼續主任務

***

### 一句話總結

> Claude Code 已經不滿足於做一個單執行緒開發助手，而是在向**「任務可拆分、角色可協作」的智能體執行平台**演化——這也是它和普通程式碼產生器越來越不一樣的地方。
