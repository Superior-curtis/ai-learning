## Claude Code 核心概念一覽

很多人第一次接觸 Claude Code 時，會被一堆名詞反覆轟炸。如果這些詞沒有先建立基本認知，後面會非常容易迷路。

這篇文章的目標不是深入講實作，而是先給你一張「核心概念地圖」。

***

### 1. QueryEngine — 核心引擎

Claude Code 的大腦調度器。它決定一項任務如何一輪一輪推進下去：理解請求 → 選擇工具 → 執行 → 觀察結果 → 調整 → 繼續。

```
使用者輸入 → QueryEngine → 選擇工具 → 執行 → 回傳結果
                              ↑                    │
                              └── 循環調度 ─────────┘
```

### 2. Tool — 執行介面

Tool 是 Claude Code 讓模型「真正動手」的方式。模型不只是輸出文字，還能透過 Tool 讀檔案、寫檔案、執行指令、搜尋網路。

Claude Code 目前有 **50+ 個工具**，涵蓋檔案操作、Shell 執行、網路請求、任務管理等類別。

### 3. AppState — 會話狀態中心

AppState 是終端界面的執行時期狀態中心。它記錄的不是某一個小組件狀態，而是整個會話當前發生了什麼。

一句話理解：AppState 決定當前這個終端會話「現在處於什麼狀態」。

### 4. Context — 專案上下文

Context 指的是 Claude Code 在每輪任務裡給模型補充的環境資訊。典型內容包括：

* 當前目錄結構
* CLAUDE.md 的專案規範
* Git 歷史與變更
* 系統提示詞

Context 解釋了 Claude Code 為什麼看起來「懂你的專案」。

### 5. Plan Mode — 規劃模式

Plan Mode 不是直接改程式碼，而是先讓 Claude Code 規劃分析，你再審查，審查通過後才開始執行。

```
你：幫我做 X
      ↓
Claude：提出方案 → 你要審查
      ↓
你：核准 → Claude 執行
```

### 6. MCP — 外部能力擴充

MCP（Model Context Protocol）讓 Claude Code 可以接入外部服務：資料庫、API、檔案系統等。不只依賴內建能力，還能連接外部世界。

### 7. LSP — 語言伺服器協定

LSP 幫助 Claude Code 取得更結構化的程式碼語義能力，例如語法檢查、跳轉定義、型別查詢。讓 Claude Code 不只是按文字看程式碼，而是能藉助語言工具鏈理解程式碼。

### 8. Skills — 經驗封裝

Skills 可以理解成任務經驗和工作方法的封裝。它不是工具本身，而更像一份「在這種情境下該怎麼做的 SOP」。

### 9. Agent — 多角色協作

Agent 意味著 Claude Code 不一定只有一個主線程助手，還可以啟動子 Agent 執行獨立任務，實現多角色協作。

### 10. Prompt / System Prompt — 動態提示詞

Claude Code 的提示詞不是一段死的文字，而是動態組裝出來的。每次任務都會根據當前上下文、專案設定、工具清單等，組合出最適合的提示詞。

| Tool | 執行介面，模型「動手」的方式 |
| Context | 專案上下文，讓 AI 懂你的專案 |
| AppState | 會話狀態中心，記錄當前發生了什麼 |
