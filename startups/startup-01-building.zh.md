# 如何打造一家 AI 公司

> 📅 2026-08-04 · 使用教學
> 想開一家 AI 公司？第一步不是選模型，而是決定站在價值鏈的哪一段。從挑楔子、AI 包裝與真護城河，到何時才該訓練自己的模型，這篇是一張務實路線圖。

---

你有一個 AI 點子。「把一個提示詞丟進 ChatGPT」人人都會，但「打造一家 AI 公司」和「呼叫一次模型 API」之間的距離，比多數人以為的更遠。這篇不是教你寫代碼，而是給你一張務實的路線圖：先決定你在價值鏈（`industry-01-value-chain`）的哪一段站穩，再談技術。

記住最底層的一件事：**所有 AI 產品，本質上都是「猜下一個字」這台機器（`llmcore-01`）外面包的一層殼。** 你真正要做的，是決定這層殼包在什麼地方、包多厚、讓誰離不開它。

## 第一個決定不是模型，是位置

幾乎每個人都想直接「用 AI 做一點東西」，但第一個該問的問題其實是：**你要站在價值鏈的哪一段賣錢。** 這決定了你的客戶、成本、對手，以及最關鍵的——護城河長什麼樣（`industry-01-value-chain`）。

* **做應用（App）**：對終端使用者或企業，直接提供一個解決問題的產品。起步最快，但要跟海量同類競爭、還得防著上游把你整合掉（`industry-03-business-models`）。
* **做基礎設施（Infra）**：賣給其他 AI 公司的工具與服務——評測、部署、代理框架、向量資料庫。客戶是開發者，離最終使用者很遠，但毛利結構像「賣鏟子」。
* **做模型（Model）**：自己煉模型、賣 API。最光鮮也最燒錢，資本門檻以億美元計算（`train-01-pretraining`），這條路幾乎不適合任何「從個人或小團隊開始」的人。

## 三個楔子一覽

| 楔子 | 賣給誰 | 起步成本 | 典型風險 |
|---|---|---|---|
| **應用 App** | 終端使用者 / 企業 | 低（按 API 用量付費） | 包裝太薄、上游整合搶飯吃 |
| **基礎設施 Infra** | 開發者 / 其他 AI 公司 | 中 | 客戶少、技術遷移成本低 |
| **模型 Model** | 所有 API 的使用者 | 極高 | 算力與資本門檻、競爭白熱化 |

## 先畫一條決策線

面對三個楔子，實務上不是「選一個最帥的」，而是照著一條決策線往下走。這個流程能幫你把「我想做 AI」變成「我該在哪一段做」：

```text
你有 AI 點子
↓ 你有數億資本 + 頂尖研究團隊嗎？
是 → 模型（Model）── 否則跳過，別多想
↓ 否：你有現成的產業痛點與客戶嗎？
是 → 應用（App）── 場景與人脈是你的優勢
↓ 否：你是優秀工程師，服務開發者？
是 → 基礎設施（Infra）
↓ 都不確定？→ 先做一個「最小應用」驗證，再往上游走
```

注意這個流程的順序：**它先淘汰「最貴的選項」，再檢視「你最特別的優勢」。** 多數人的問題不是「三個選一個」，而是花了太多時間幻想自己該做模型，卻連第一個付費使用者都還沒有。

## 挑楔子，其實是挑「你的優勢」

不是每個人都適合任一段。挑楔子的實用標準，不是「哪段最賺錢」，而是「**哪段最吃我的既有優勢**」：

1. **你懂某個產業的痛點** → 做應用。你最值錢的是場景知識與人脈，不是模型技術。
2. **你是優秀的工程師、使用者量也不大** → 做基礎設施。你把工程能力賣給其他開發者。
3. **你握有幾億美元的資金與頂尖研究團隊** → 才考慮模型。否則請把這個選項留到很晚再想。

一句話：**不要因為「模型很熱門」就去煉模型，要因為「我確實有別人難以複製的關鍵資源」才往上游走。**

## 「AI 包裝」不是髒話——它是起點

「這只是個 AI wrapper」常被做成嘲笑的梗。但請冷靜看：**wrapper 不是問題，只有 wrapper 才是問題。** 任何產品剛誕生時，都是對「猜下一個字」這台機器的一層薄殼；評判它不是看「它有沒有接 API」，而是看：

* 這層殼裡，有沒有別人不容易複製的**工作流、資料、整合或分發**？
* 還是說，任何人把我抄走，只需要一天加一個 API key？

後者才是「只是個 wrapper」的致命之處——不是因為它包了 AI，而是因為**它沒有包出自己的東西**。

## 用現有 API 快速上線

對絕大多數新創，正確的第一個動作不是自己煉模型，而是**把現成 API 接進來、立刻上路**。把省下來的時間花在真正重要的三件事上：

#### 驗證需求

事情在「有沒有人真的付錢」，而不是「模型多聰明」。用最薄的版本每天賣出去幾單，感受一下市場溫度。

#### 打磨工作流

找出使用者為什麼留下來：是節省時間、省錢，還是做出原本做不到的事？把這個「非 AI 不可」的部分磨到極致。

#### 累積資料與反饋

每一筆真實使用，都是你未來築牆的原料。資料與工作流，比模型本身更難被複製。\n\n→ 想深入：rag-01-what-is-rag

API 的成本結構你要心裡有數：毛利被**推理成本**壓著（`econ-01-inference-cost`）。用量小的時候它無所謂，用量大了它會決定你能不能活——所以「先快速上線」的同時，要一直盯著這個分母。

## 從第一版到第一批付費使用者

「上線」很容易，「有人付錢」是另一回事。從第一版走到第一批付費使用者，通常得過三個關卡：

1. **找人試用**：不是找朋友捧場，而是找「真有這個問題、且現在就痛」的人。免費幫他們做，換真實使用與反饋。
2. **把使用變成付費**：從免費到付費是質變。定價不要拍腦袋，而是從「你幫客戶省下的時間或賺到的錢」反推。
3. **重複銷售**：一個客戶付費不代表產品成立；同一套流程被第二、第三個客戶接受，才是「可重複」的訊號。

一個誠實的自我檢驗：**如果關掉你的產品，有多少使用者會來敲門？** 答案是零或接近零，代表你的產品還只是「有趣」，不是「必要」。

## 何時才考慮自己的模型或微調

接 API 有一天會撞上天花板：成本、延遲、隱私、對輸出的控制、對某領域術語的精準度。但這不代表「以後得自己做模型」。你自己面對的選擇，往往是**微調 vs RAG**，而不是「全部自己煉」——取捨的完整比較在 `finetune-01-finetune-vs-rag`。

一個粗略的判斷流程：

```text
新產品 → 先接現成 API
↓ 想強化某領域知識？
RAG（檢索現有資料）→ 通常先試，便宜、可更新
↓ RAG 不夠、要穩定「風格/格式/行為」？
微調（LoRA）→ 成本可控，試水溫
↓ 需要完全控制權重，或用量大到自架划算？
才考慮自建或開源權重部署（models-01-open-vs-closed）
```

關鍵原則：**先用最便宜的工具解決，等瓶頸真的出現、而且你算得出「自建省多少錢」時，再考慮換檔。** 幾乎沒有新創是「一上路就該自己煉模型」的，正如 `industry-03-business-models` 提醒的，規模決定打法——小，就用 API；大到綁定毛利，才談自架。

## 團隊：AI 新創怎麼組隊

一個人能起步，但「從 demo 走到付費產品」很少只靠一個人。三個角色最關鍵：

| 角色 | 做什麼 | 找不到時會發生什麼 |
|---|---|---|
| **產品 / 場景人** | 定義痛點、跟客戶對話、定優先順序 | 做出「工程上很酷但沒人買」的東西 |
| **工程師** | 把模型呼叫包成可靠、可擴充的產品 | 想法永遠停在 prototype |
| **會計 / 商業腦** | 算單元經濟、盯燒錢、設計計價 | 使用者很多，公司卻一直虧 |

你可以身兼數職，但要**誠實面對「哪一格最弱」**——那通常是你該第一個找人補上的位置，而不是你最愛做的位置。

## 常見的起步錯誤

把同一個錯誤重複一百次的新創很多，以下是出現率最高的幾種：

#### 過度工程化

花了三個月自建評測框架、微調管線，卻還沒有一個付費使用者。正確順序是先賣出第一單，再談工程品味。

#### 害怕「抄襲」

覺得「只要我會接 API，別人也會」。對，所以你要快、要磨場景，而不是指望技術壁壘。

#### 模型焦慮

整天追著最新模型跑，產品卻沒進步。使用者不認得你用的是哪顆模型，只認得結果。

#### 不敢收錢

免費到底，換來一堆「很酷但不會付費」的使用者。早點定價，是驗證需求最快的方式。

## 真正能築牆的是什麼

把「AI 包裝」說清楚後，回答那個真正的問題：**什麼東西是別人複製不了的？** 多半不是模型，而是底下這幾樣：

* **獨有資料與工作流**：別人就算拿到同一顆模型，也沒有你和客戶累積出的流程與資料。
* **分發與通路**：使用者為什麼會經過你，而不是直接用 ChatGPT？關鍵是「你在的地方」與「你的整合」。
* **信任與合規**：醫療、金融、政府場景，客戶買的是「你能在我的伺服器上安全、負責地跑」——這是 `models-01-open-vs-closed` 那篇介紹的開放權重+服務模式的價值。

把這幾樣築起來，就算明天有一顆「更強十倍」的免費模型發布，你也不會一夜間消失——因為使用者是為了「你包的那一層」留下來的。

> 要記住的一件事：打造 AI 公司，第一步不是挑最強模型，而是在價值鏈（industry-01-value-chain）上選一個「楔子」，接著用現有 API 快速驗證需求，把時間花在別人複製不了的資料、工作流與分發上——模型本身，很少是那個護城河。

## 下一步

「怎麼把這家公司做出來」的大方向清楚了。但做產品是一回事，維持它生存是另一回事：**錢從哪裡來、這家公司值多少錢**——這就是 `startup-02-funding` 的主題。

#### Q: 對一家剛起步的 AI 新創，最務實的起步方式通常是哪一種？

* 第一天就投入鉅資訓練自己的旗艦模型

* 挑好價值鏈上的楔子，用現有 API 快速上線，先驗證真實需求

* 等 AGI 誕生再開始做產品

* 把所有時間花在比較不同模型的跑分上

> 💡 多數新創的優勢在於場景、資料與分發，而不是模型技術本身。正確的第一步是選好楔子、用現成 API 快速驗證需求，把資源投入別人難以複製的工作流與資料上。
