# Apple Silicon 與 NVIDIA：在你的硬體上跑模型

> 📅 2026-08-01 · 深入研究
> 統一記憶體 vs VRAM、Metal vs CUDA：從頻寬到記憶體，搞懂你的機器適合跑什麼模型。

---

上一篇談到量化與 GGUF，這一篇回到硬體。很多人第一個問題是：「我的 MacBook 跑得動嗎？」答案取決於一個關鍵：你的記憶體有多少、記憶體頻寬有多高。這一篇把 Apple Silicon 與 NVIDIA 兩條路一次講清楚。

***

## 兩種截然不同的架構

### Apple Silicon：統一記憶體

Mac 的 M 系列晶片（M1/M2/M3/M4）把 CPU、GPU、記憶體全部放在同一顆晶片上，CPU 和 GPU **共用同一塊記憶體**，不需要把資料複製來複製去。

**好處：**

* 記憶體池就是你的「顯存」：64GB 的 MacBook 等於有 64GB 可供模型使用
* 記憶體容量決定能跑多大的模型，容量大、價格相對便宜

### NVIDIA：獨立的 VRAM

NVIDIA 顯卡是一張插在 PCIe 上的獨立卡，有自己專屬的視訊記憶體（VRAM），顯示卡與主記憶體之間要透過匯流排傳資料。

**好處：**

* 記憶體頻寬極高、延遲低
* 生態系成熟：CUDA、cuDNN、TensorRT

**限制：**

* VRAM 固定：買了 24GB 就是 24GB，不能事後加

***

## Metal vs CUDA：兩套軟體棧

硬體之外，真正決定你能跑什麼的是軟體。

### CUDA（NVIDIA）

CUDA 是 NVIDIA 的通用平行計算平台，也是整個 AI 生態系的「標準」。PyTorch、TensorFlow、vLLM 這些工具的 GPU 支援，幾乎都以 CUDA 為第一優先。

### Metal / MLX / MPS（Apple）

Apple 的路線比較分散：

* **Metal**：底層 GPU API，llama.cpp 走這條
* **MLX**：Apple 自己的陣列框架，針對 Apple Silicon 深度最佳化
* **MPS**：PyTorch 在 Mac 上的後端，對應 `torch.device("mps")`

好消息是：llama.cpp 同時支援 Metal 與 CUDA。**同一套工具、同一個 GGUF 檔案，在兩邊都能跑**，只是背後的加速層不同。

***

## 記憶體頻寬才是關鍵

LLM 推理是「記憶體密集」的工作：每次生成一個 token，都要把整個模型的權重讀一遍。所以**跑多快，主要看記憶體頻寬，而不是算力**。

### 各平台約略頻寬

| 平台 | 記憶體頻寬（約略） |
|------|------------------|
| M1 / M2 基礎款 | ~68-100 GB/s |
| M1 Pro / M2 Pro | ~200 GB/s |
| M1 Max / M3 Max | ~400 GB/s |
| M4 Max | ~546 GB/s |
| M2 Ultra | ~800 GB/s |
| RTX 4090 | ~1000 GB/s |
| RTX 5090 | ~1790 GB/s |
| H100 | ~3350 GB/s |

頻寬越高，同樣的模型每秒能生成的 token 越多。一張 RTX 4090 的頻寬約是 M3 Max 的 2.5 倍。

***

## 在 Mac 上跑得很順的模型

如果你的目標是**個人使用、開發輔助、實驗**，Apple Silicon 的體驗其實非常好：

* 7B-8B 量化模型（Q4）：M 系列大部分晶片都能跑出 15-40 tok/s，足夠順暢
* 14B：高階晶片（Max / Ultra）流暢，Pro 等級稍慢但可用
* 32B：Max / Ultra 上可用，速度中等
* 70B：只有 64GB+ 的 Max / Ultra 能載入，速度降到個位數 tok/s

**關鍵數字：** 一個 7B 模型 Q4 量化約 4-5GB，32GB 記憶體的 Mac 綽綽有餘；一個 70B 模型 Q4 約 40GB，需要 64GB 以上的機器。

### Mac 的強項

* 隨身：筆電帶著走，隨時有 AI
* 省電：跑推理時功耗遠低於滿載顯卡
* 安靜：不需要額外電源或散熱
* 大記憶體選項：最高可到 128GB

***

## 一定要 NVIDIA 的場景

有些工作 Mac 做起來很吃力，需要真正的 GPU：

* **訓練與微調**：尤其全參數微調，CUDA + 大 VRAM 幾乎是必需品
* **70B+ 大型模型**：需要高頻寬與大量記憶體
* **多使用者伺服器**：同時服務多人，需要高吞吐
* **追求極致速度**：對每 token 延遲敏感的應用
* **複雜生態系工具**：很多框架只有 CUDA 路徑

### NVIDIA 的強項

* 頻寬與吞吐遠高於 Mac
* 多卡擴充（NVLink、多 GPU）
* 完整工具鏈：vLLM、TensorRT、DeepSpeed
* 業界標準，社群文件最多

### NVIDIA 的限制

* VRAM 固定且貴：消費級 8-32GB，工作站才到 48GB+
* 功耗與散熱：一張 4090 滿載約 450W
* 需要桌上型或伺服器環境

***

## 一張對照表

| 面向 | Apple Silicon | NVIDIA GPU |
|------|--------------|-----------|
| 記憶體模型 | 統一記憶體（RAM 即 VRAM） | 獨立 VRAM |
| 記憶體上限 | 高達 128GB（可跑 70B+） | 消費級最多 32GB |
| 頻寬 | 100-800 GB/s | 300-3350 GB/s |
| 軟體棧 | Metal / MLX / MPS | CUDA / cuDNN / TensorRT |
| 適合 | 7B-32B、個人使用 | 70B+、訓練、伺服器 |
| 功耗 | 低（10-70W） | 高（200-575W） |
| 可攜性 | 筆電內建 | 需要插卡 / 主機 |

***

## 怎麼選：按需求決定

**選 Mac，如果：**

* 你主要跑 7B-14B，偶爾 32B
* 你需要攜帶性、低功耗、安靜
* 你想用同一台機器日常開發兼跑 AI

**選 NVIDIA，如果：**

* 你要微調或訓練模型
* 你要跑 70B+ 或同時服務多人
* 你要追求每秒生成速度的極致
* 你已有或願意投資一台工作站

### 最務實的路線

如果你兩邊都要碰，優先選 **llama.cpp + GGUF** 這種跨平台工具，讓同一套工作流程在 Mac 與 NVIDIA 之間平滑移動。先在你的 Mac 上把流程跑通，需要更大規模時再遷到 GPU 機器。

***

## 總結

* 模型能跑多大，看**記憶體容量**；跑多快，看**記憶體頻寬**
* Mac 的統一記憶體讓「大容量」便宜，適合個人與中型模型
* NVIDIA 的 VRAM 貴而固定，但頻寬與軟體生態領先
* llama.cpp 是兩邊共通的那塊拼圖
