# 給開發者的 AI 學習路徑：從「會問」到「會建」

> 📅 2026-08-04 · 使用教學
> 不靠死背框架，而是按著「模型怎麼想」走一條路：先懂下一個詞，再學提示、RAG、Agent 與 MCP，最後會評估、會部署。

---

你已經會寫程式了，這是你的優勢。框架會來會走，套件會紅會衰——但有一個東西不變：**模型怎麼想**。而它想的方式，一句話就能講完：預測下一個詞（`llmcore-01`）。

這一篇不教你背任何框架，而是給你一條可以照著走的學習路徑。每一步都建立在上一步之上，從「會問 AI」一直走到「會把 AI 部署成產品」。走完，你就不是在使用者那層打轉，而是能自己建構的開發者。

## 為什麼先學心智模型，而不是先學框架

初學者最常犯的錯，是直接跳進某個套件——LangChain、Pinecone、AutoGen——然後發現自己只是在「連 API」，一點都不理解自己在做什麼。框架更新一次，你的知識就過期一次。

先建心智模型，所有框架都變成「這個心智模型的某種包裝」：

* 提示工程 = 用文字縮小模型的選擇範圍。
* RAG = 把知識先放進上下文，讓它不要憑空猜。
* Agent = 讓模型在「行動→看結果→再行動」的迴圈裡跑。
* MCP = 給這個迴圈一個標準的「接工具」介面。

你先把「猜下一個詞」這台機器想清楚，上面四件事就全是推論出來的，不是背出來的。

> 一句話記住整條路徑的核心：所有 AI 應用，都只是在「預測下一個詞」的機器外面，加上知識、工具與迴圈。 心智模型是根，框架只是葉子。

## 學習路徑：六個步驟

下面是這條路。每一步都對應本書裡一個系列，照順序走，每一步都在替下一步鋪路。

#### 步驟一：建立心智模型

讀 llmcore-01-next-token，真正想通「預測下一個詞」是什麼意思。接著讀 token（02）、上下文（03）、抽樣（04）。這三篇讓你知道它「怎麼想」，所有後續技巧都是從這裡推出來的。\n\n→ 動手：打開一個模型，逐字看它怎麼接話。

#### 步驟二：提示工程

讀 prompt-01-basics 到 prompt-04-robustness。目標不是背模板，而是學會「指令、背景、限制」三件事，以及系統提示怎麼讓輸出穩定。寫十個提示，記錄哪些改動改變了結果。

#### 步驟三：RAG——把知識接進來

讀 rag-01-what-is-rag 到 rag-04-evaluating。學到「怎麼讓模型回答它沒學過、但你的文件裡有的東西」：切塊、索引、混合檢索、重排。這是把模型從「萬事通」變成「你的助手」的關鍵一步。

#### 步驟四：Agent——讓它行動

讀 agents-01-what-is-agent 與 agents-04-first-agent。理解「迴圈」：模型提出動作、工具執行、結果回饋、再決定下一步。先別碰重框架，用最原始的迴圈寫一個能查資料的 agent。

#### 步驟五：MCP——連接你的工具

讀 mcp-01-what-is-mcp。MCP 是「工具與資料」的標準插頭，讓 agent 能接上你自己的 API、資料庫、檔案系統。把你在步驟四寫的 agent，改成透過 MCP 接上真實工具。

#### 步驟六：評估與部署

讀 models-06-evaluation。沒有評估，你只是在「感覺它變好了」。建一組小測試集，每次改動都跑一遍。然後把成品部署出去，監控、迭代。\n\n→ 這一步把「範例」變成「產品」。

## 路徑背後的邏輯

這六步不是隨意排的，每一層都在替下一層拆掉一個「看不見的假設」：

* 不先懂心智模型，提示工程就只是背咒語，遇到問題不知道往哪調。
* 不先學會提示，RAG 的效果再怎麼調都像碰運氣——你根本判斷不出問題出在檢索還是生成。
* 不先做過靜態的 RAG，就跳進 Agent，你會分不清「模型不會用工具」和「檢索結果太爛」。
* 不先懂 Agent，MCP 對你來說只是另一個 API 格式，而不是「給迴圈接工具」的標準。

**每一層都在替你建立「下一步出問題時，你能定位是哪一層」的直覺。** 這是框架教學給不了你的東西。

## 每一層的輸入與輸出

把六步壓成四層，每一層的介面都長這樣：

| 層 | 你給它的 | 它回你 | 最常見的失敗 |
|---|---|---|---|
| **提示** | 指令、背景、限制 | 一段輸出 | 回答太泛泛、語氣不對 |
| **RAG** | 文件＋問題 | 有來源、可追溯的回答 | 檢索不到對的文件 |
| **Agent** | 任務＋可用工具 | 一連串的行動與結果 | 迴圈空轉、繞圈子 |
| **MCP** | 工具的定義 | 標準化的連線 | 工具濫用、權限失控 |

這張表最大的用處是偵錯：出問題時，先問「是哪一層」。回答泛泛，往提示層查；答得自信但錯，往檢索層查；行動亂跑，往 agent 的迴圈查。**能把問題歸到正確的層，就解決了一半。**

## 時間怎麼分配

照這條路走，時間不必平均分配。務實的比例大概長這樣：

* **心智模型＋提示（步驟一、二）**：花兩成的時間，但值得，因為它讓後面所有步驟少走冤枉路。
* **RAG（步驟三）**：花三成。它最容易做出「看得見的價值」——把模型從萬事通變成懂你文件的人。
* **Agent 與 MCP（步驟四、五）**：花三成。這裡最容易卡關，因為你要開始處理「不確定性」。
* **評估與部署（步驟六）**：花兩成。沒有這部分，前面的都只是 demo。

比例如是參考，不是律法。重點是：**別把八成時間花在最後兩成價值的炫技上。**

## 評估：知道自己在進步

學習路徑的中間很容易迷路：「我是不是變強了？」別靠感覺，建一個最小評估集。

```text
你的一組測試問答 ──→ 每次改動後都跑一遍 ──→ 分數上升？保留；下降？回滾
↑____________________←______________________↓
```

不用複雜。挑十到二十個你真正在乎的問題（它們是「你的」標準，不是別人的），寫下理想答案的關鍵點。之後每次改動——換提示、加檢索、換模型——都跑一遍，看分數往哪走。這比任何「感覺它變聰明了」都可靠，也是 `models-06-evaluation` 的精神。

評估到一半不用追求完美。一開始，讓模型自己幫你打分（LLM-as-judge）就夠用了；跑個幾輪、分數穩定之後，再慢慢補上人工複核的樣本。**評估的目標不是「科學」，是「讓你能分辨改動的方向」。**

## 別掉進的三個坑

* **框架優先**。看到新套件就想學，結果 API 會換、心智模型不會。先紮根，框架只是順手。
* **只調提示、不建評估**。調提示很快，但沒有評估你只是在過度擬合當下的例子。
* **一步到位做「全能 Agent」**。跳過步驟一～三，直接想要一個能自主完成一切的 agent，最後往往在「不知道問題出在哪」裡燒時間。拆小、逐步驗證，比一次到位快得多。

三者的共同點：都是在「還沒有分層直覺」的時候就想跳級。路徑的價值，就在於它逼你先建立那層直覺，再談速度。

## 從範例到產品

學到步驟六，你已經具備把一個範例變成產品的全部材料。挑一個真實問題，規模要小但要是真的：

1. **選題**：一個你每天都在做的事——讀報告、回覆信件、整理資料——它重複、規則、費時。
2. **建構**：用 RAG 餵進相關文件，用提示定型輸出格式，用 agent 讓它可以「查完再答」。
3. **評估**：建那二十題的測試集，把它調到穩定。
4. **部署**：接上你的日常工作流，跑兩週，記錄它省下的時間與犯的錯。

一輪下來，你學到的不只是工具，而是「**建 AI 產品 = 心智模型 + 知識 + 工具 + 迴圈 + 評估**」這套完整的方法。

別把題目選得太大。「幫全公司做一個 AI 助理」不是一個好專案，「把我自己每天讀報告、整理摘要的十五分鐘自動化」才是。**小到兩個禮拜能做完、大到值得做，就是好的第一步。** 完成之後再看它能長大的方向。

#### Q: 為什麼學習路徑要把「心智模型」排在「框架」之前？

* 因為框架都需要付費才能學

* 因為提示、RAG、Agent、MCP 都是「預測下一個詞」的包裝，先懂核心才能定位問題在哪一層

* 因為心智模型比框架更容易背

* 因為框架會讓程式變慢

> 💡 提示、RAG、Agent、MCP 本質上都是同一台「預測下一個詞」的機器加上不同的外掛。先懂核心，遇到問題時你才知道是提示、檢索、工具還是迴圈出了問題——這是框架教學給不了的分層直覺。
